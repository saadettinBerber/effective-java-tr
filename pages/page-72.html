Item 31: Use bounded wildcards to increase API flexibility

Parametreli türler değişmezdir (invariant) — List<String>, List<Object>'in alt türü değildir. Ancak bazen daha fazla esnekliğe ihtiyacımız vardır. Sınırlı joker türleri (bounded wildcard types) bu esnekliği sağlar:

Parameterized types are invariant. Bounded wildcard types provide additional flexibility:

// Sınırlı joker türü olmadan — çok kısıtlayıcı public void pushAll(Iterable<E> src) { ... } // Iterable<Integer>'ı Stack<Number>'a geçiremezsiniz! // Sınırlı joker türü ile — esnek public void pushAll(Iterable<? extends E> src) { ... } // Artık Iterable<Integer>'ı Stack<Number>'a geçirebilirsiniz! // Benzer şekilde popAll için public void popAll(Collection<? super E> dst) { ... }

PECS kuralı — Producer Extends, Consumer Super:

• Parametre üretici (producer) ise — yani T örnekleri sağlıyorsa → <? extends T>
• Parametre tüketici (consumer) ise — yani T örneklerini kabul ediyorsa → <? super T>

Bu kural Comparable ve Comparator ile de geçerlidir — her ikisi de tüketicidir. Bu nedenle Comparable<? super T> ve Comparator<? super T> tercih edin.

Önemli kural: Dönüş değerlerinde joker türü kullanmayın! Joker türleri yalnızca parametrelerde kullanılmalıdır — aksi halde istemciler de joker türleriyle uğraşmak zorunda kalır.

Tür çıkarımı (type inference) düzgün çalışmazsa, açık tür tanığı (explicit type witness) kullanın: Union.<Number>union(integers, doubles)

PECS: Producer → extends, Consumer → super. Don't use wildcards in return types. If type inference fails, use explicit type witness.

🔍 Kavramlar: 🔍 Concepts:

PECS Kuralı

Producer Extends, Consumer Super

Üretici (Producer): Parametreden veri okuyorsunuz → <? extends T>
Tüketici (Consumer): Parametreye veri yazıyorsunuz → <? super T>

Örnek: pushAll(Iterable<? extends E> src) — src üretici (veri sağlıyor)
popAll(Collection<? super E> dst) — dst tüketici (veri alıyor)

Producer Extends, Consumer Super. Read from → extends. Write to → super.
