// Public final alana sahip Singleton (Singleton with public final field) public class Elvis { public static final Elvis INSTANCE = new Elvis(); private Elvis() { ... } public void leaveTheBuilding() { ... } }

Private yapıcı metot (constructor), sadece public statik final alan olan Elvis.INSTANCE ilklendirilirken bir kez çağrılır. Public veya protected bir yapıcı metodun olmaması, "mono-elvis" bir evreni garanti eder: Elvis sınıfı ilklendirildiğinde geriye tam olarak tek bir Elvis örneği (instance) var olacaktır—ne daha fazla ne daha az. Bir istemcinin (client) yapacağı hiçbir şey bunu değiştiremez, ufak bir istisna dışında: ayrıcalıklı bir istemci, AccessibleObject.setAccessible metodunun yardımıyla reflection (yansıtma) aracılığıyla (Madde 65) private yapıcı metodu çalıştırabilir. Bu tür saldırılara karşı kodunuzu korumanız gerekirse, yapıcı metodu değiştirip ikinci bir örnek oluşturulmak istendiğinde itiraz etmesini (exception fırlatmasını) sağlayabilirsiniz.

Singleton uygulamanın ikinci yaklaşımında ise dışarıya açılan üye (public member), statik fabrika metodudur (static factory method):

The private constructor is called only once, to initialize the public static final field Elvis.INSTANCE. The lack of a public or protected constructor guarantees a "monoelvistic" universe: exactly one Elvis instance will exist once the Elvis class is initialized—no more, no less. Nothing that a client does can change this, with one caveat: a privileged client can invoke the private constructor reflectively (Item 65) with the aid of the AccessibleObject.setAccessible method. If you need to defend against this attack, modify the constructor to make it throw an exception if it’s asked to create a second instance.

In the second approach to implementing singletons, the public member is a static factory method:

// Statik fabrika (static factory) ile Singleton public class Elvis { private static final Elvis INSTANCE = new Elvis(); private Elvis() { ... } public static Elvis getInstance() { return INSTANCE; } public void leaveTheBuilding() { ... } }

Elvis.getInstance metoduna yapılan tüm çağrılar aynı nesne referansını döndürür ve (daha önce bahsedilen kural dışı durum hariç) bir başka Elvis örneği asla yaratılmaz.

Public alan (public field) yaklaşımının temel avantajı, API'nin sınıfın bir singleton olduğunu çok açık bir şekilde belirtmesidir: public statik alan final olduğu için, o alan daima aynı nesneye referans edecektir. Bu yaklaşımın ikinci avantajı ise daha basit olmasıdır.

Statik fabrika (static factory) yaklaşımının bir avantajı, API'yi değiştirmeden sınıfın singleton olup olmayacağı konusundaki fikrinizi değiştirme esnekliği sunmasıdır. Fabrika metodu yegane (sole) örneği döndürür ancak ileride değiştirilebilir; örneğin onu çağıran her iş parcacığı (thread) için ayrı bir örnek fırlatabilir. İkinci avantajı ise uygulamanız gerektiriyorsa jenerik (generic) bir singleton fabrikası yazabilmenizdir (Madde 30). Statik fabrikalar kullanmanın son bir avantajı da bu metot referansının (method reference) bir supplier (sağlayıcı) olarak kullanılabilmesidir, örneğin Elvis::instance aslında bir Supplier<Elvis> dir. Eğer uygulamanız için bu saydığımız avantajlar kullanılmayacaksa public alan yaklaşımı daha çok tercih edilmelidir.

Bu iki yaklaşımdan herhangi birini kullanan bir singleton sınıfını serileştirilebilir (Chapter 12) yapmak için sınıfa basitçe implements Serializable eklemek yeterli değildir. Singleton garantisini koruyabilmek için, örnekteki tüm alanları transient (geçici) olarak deklare edin ve (Madde 89'da bahsedilen) kendi readResolve metodunuzu yazın. Aksi taktirde (örneğin de-serileştirme esnasında) yepyeni bir örnek yaratılacaktır, bu durumda elinizde birden çok sinsi şekilde varolan Elvis'ler olabilir. Bunu önlemek için, Elvis sınıfına şu readResolve metodunu eklemelisiniz:

All calls to Elvis.getInstance return the same object reference, and no other Elvis instance will ever be created (with the same caveat mentioned earlier).

The main advantage of the public field approach is that the API makes it clear that the class is a singleton: the public static field is final, so it will always contain the same object reference. The second advantage is that it’s simpler.

One advantage of the static factory approach is that it gives you the flexibility to change your mind about whether the class is a singleton without changing its API. The factory method returns the sole instance, but it could be modified to return, say, a separate instance for each thread that invokes it. A second advantage is that you can write a generic singleton factory if your application requires it (Item 30). A final advantage of using a static factory is that a method reference can be used as a supplier, for example Elvis::instance is a Supplier<Elvis>. Unless one of these advantages is relevant, the public field approach is preferable.

To make a singleton class that uses either of these approaches serializable (Chapter 12), it is not sufficient merely to add implements Serializable to its declaration. To maintain the singleton guarantee, declare all instance fields transient and provide a readResolve method (Item 89). Otherwise, each time a serialized instance is deserialized, a new instance will be created, leading, in the case of our example, to spurious Elvis sightings. To prevent this from happening, add this readResolve method to the Elvis class:

// singleton özelliğini korumak için readResolve metodu private Object readResolve() { // Tek hakiki (true) Elvis'i döndürün ve // çöp toplayıcısına (garbage collector) Elvis taklitçisini temizelettirin. return INSTANCE; }

Singleton uygulamanın üçüncü bir yolu, tek elemanlı bir enum (single-element enum) deklare etmektir:

A third way to implement a singleton is to declare a single-element enum:

// Enum singleton - tercih edilen yaklaşım public enum Elvis { INSTANCE; public void leaveTheBuilding() { ... } }

Bu yaklaşım, public final alan yaklaşımına benzer ancak daha az kod gerektirir (concise), serileştirme altyapısını bedavaya sağlar ve gelişmiş serileştirme ya da reflection (yansıma) saldırıları karşısında dahi birden fazla örnek oluşturulmasına karşı demir gibi sert bir garanti sağlar. Bu yaklaşım biraz tuhaf hissettirse de, tek elemanlı bir enum tipi genellikle bir singleton uygulamak için en iyi yoldur. Singleton değeriniz Enum dışında farklı bir üst sınıftan türetilecekse (extend edilecekse) bu yöntemi uygulayamazsınız, ama enum sınıfları içlerine farklı interface (arayüz) tiplerinden implemente edebilirler.

This approach is similar to the public field approach, but it is more concise, provides the serialization machinery for free, and provides an ironclad guarantee against multiple instantiation, even in the face of sophisticated serialization or reflection attacks. This approach may feel a bit unnatural, but a single-element enum type is often the best way to implement a singleton. Note that you can’t use this approach if your singleton must extend a superclass other than Enum (though you can declare an enum to implement interfaces).

Serialization (Serileştirme) / Serialization

Serileştirme, bellekteki bir nesneyi diskte saklayabileceğiniz veya ağ üzerinden gönderebileceğiniz bir bayt dizisine dönüştürme işlemidir. Singleton'lar serileştirilip tekrar belleğe yüklendiğinde (de-serileştirme), Java orijinal nesne yerine yepyeni bir örnek yaratır ve bu da Singleton garantisini (sadakatini) bozar. Enum kullanmak bunu JVM seviyesinde otomatik çözer.

Serialization is the process of translating a data structure or object state into a format that can be stored or transmitted and reconstructed later. When Singletons are deserialized, Java forces a new instance, breaking the Singleton property. Using an Enum solves this neatly as the JVM handles it automatically.

💡 Enum kullanmadığınız singleton sınıflarında, yeni kopya yaratılmasını önlemek için readResolve() metoduna ihtiyacınız vardır.
💡 If you're not using an enum for your Singleton, you must provide a readResolve() method to prevent multiple instances upon deserialization.

Reflection (Yansıma) / Reflection

Reflection (Yansıma), bir Java programının çalışma zamanında (runtime) kendini incelemesi ve değiştirmesidir. Private yapılmış bir constructor'ı bile setAccessible(true) ile public gibi kullanılabilir hale getirebiliriz.

Reflection is the ability of a program to examine and modify its structure and behavior at runtime. Through reflection, even a private constructor can be invoked via setAccessible(true).

✗ TEHLİKE — Yansıma ile Constructor Hack'lemek
Constructor<Elvis> constructor = Elvis.class.getDeclaredConstructor(); constructor.setAccessible(true); // Korumaları aşıyoruz! Elvis fakeElvis = constructor.newInstance(); // Alın size 2. Elvis!
💡 Kötü amaçlı bir kod bu şekilde singleton kuralınızı delebilir. Bunu engellemenin en iyi yolu ya constructor içinde static sayacı kontrol edip exception atmak ya da yine Enum (en ideali!) kullanmaktır, çünkü yansıma (reflection) yoluyla enum başlatmak tamamen JVM tarafından yasaklanmıştır.
💡 Malicious (or buggy) code can break the singleton rule using this. The best defense is to throw an Exception from the constructor if an instance already exists, or just use an Enum which strictly prohibits instantiation via reflection.

Supplier Function (Sağlayıcı) / Supplier

Supplier<T>, Java 8 ile gelen ve parametre almadan belirli bir türde değer üreten bir fonksiyonel arayüzdür. Elvis.getInstance() (statik fabrika) yöntemi, fonksiyon bekleyen yerlerde doğrudan Elvis::getInstance referansı kullanılarak Supplier yerine çok rahat geçirilir.

Supplier<T> is a functional interface from Java 8 that takes no arguments and returns a value. A static factory method (Elvis.getInstance) can be used anywhere a Supplier is needed via method reference (Elvis::getInstance).

✓ İYİ — Metod referansı ile kullanımı
public void performTask(Supplier<Elvis> elvisSupplier) { Elvis elvis = elvisSupplier.get(); elvis.leaveTheBuilding(); } // Kullanım performTask(Elvis::getInstance);
