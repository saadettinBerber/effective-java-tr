Madde 39: Adlandırma Kalıpları Yerine Anotasyonları Tercih Edin

Item 39: Prefer annotations to naming patterns

Eskiden bazı çerçeveler (frameworks) adlandırma kalıpları (naming patterns) kullanırdı — örneğin JUnit 3'te test metotlarının testXxx ile başlaması gerekiyordu. Bu yaklaşımın sorunları: yazım hataları sessizce görmezden gelinir, belirli program öğeleriyle sınırlama yapılamaz ve parametre ilişkilendirmenin iyi bir yolu yoktur.

Anotasyonlar tüm bu sorunları çözer. Kendi anotasyonunuzu tanımlayabilirsiniz:

Naming patterns (e.g., testXxx in JUnit 3) have problems: typos silently ignored, no compile-time enforcement. Annotations solve everything:

// İşaretleyici anotasyon (marker annotation) @Retention(RetentionPolicy.RUNTIME) @Target(ElementType.METHOD) public @interface Test { } // Parametreli anotasyon — beklenen istisna @Retention(RetentionPolicy.RUNTIME) @Target(ElementType.METHOD) public @interface ExceptionTest { Class<? extends Throwable> value(); }

Madde 40: @Override Anotasyonunu Tutarlı Kullanın

Item 40: Consistently use the Override annotation

@Override yalnızca metot bildirimlerinde kullanılabilir ve üst türdeki bir metot bildirimini ezdiğinizi (override) belirtir. Bu anotasyonu tutarlı kullanmak, sizi ciddi hatalardan korur.

Klasik hata: equals(Bigram other) yazmak — bu Object.equals(Object)'i ezmez, aşırı yükler (overloads)! @Override eklenirse derleyici hatayı yakalar.

Kural: Ezdiğini düşündüğünüz her metoda @Override ekleyin. Tek istisna: soyut metotları uyguladığınızda — derleyici zaten uygulamadığınızda hata verir (ama yine de ekleyin).

@Override prevents accidental overloading instead of overriding. Classic bug: equals(Bigram other) overloads instead of overriding. Add @Override to every method you believe overrides a superclass method.

Madde 41: Tür Tanımlamak İçin İşaretleyici Arayüzleri Kullanın

Item 41: Use marker interfaces to define types

İşaretleyici arayüz (marker interface), hiçbir metot bildirimi içermeyen, yalnızca bir sınıfın belirli bir özelliğe sahip olduğunu belirten bir arayüzdür — Serializable gibi. İşaretleyici anotasyon (marker annotation) ise @Override gibi bir anotasyondur.

İşaretleyici arayüzün avantajı: Bir tür tanımlar — derleme zamanında hata yakalanabilir. ObjectOutputStream.writeObject aslında Serializable gerektirmeli ama Object kabul eder — çalışma zamanında hata verir!

Kurallar: İşaretli nesnelerin metot parametresi olarak geçmeyi planlıyorsanız → arayüz kullanın (derleme zamanı tür denetimi). Sınıf dışı program öğelerini işaretliyorsanız ya da çerçeve anotasyonları kullanıyorsanız → anotasyon kullanın.
