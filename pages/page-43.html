Chapter 3 — Item 10: equals — Tutarlılık & Null-olmama
↩ Önceki sayfadan devam — Madde 10: Tutarlılık (Consistency) ve Null-olmama (Non-nullity)

Tutarlılık (Consistency) — equals sözleşmesinin dördüncü gereksinimi, eğer iki nesne eşitse süresiz olarak eşit kalmaları gerektiğini (ve eğer eşit değilse süresiz olarak eşit olmamaları gerektiğini) söyler. Başka bir deyişle, değişebilir (mutable) nesneler farklı zamanlarda farklı nesnelere eşit olabilir; ancak değişmez (immutable) nesneler olamaz. Bir sınıf yazarken, değişmez olup olmayacağını dikkatle düşünün (Madde 17). Eğer değişmez olması gerektiğine karar verirseniz, eşit nesnelerin sonsuza kadar eşit ve eşit olmayan nesnelerin sonsuza kadar eşit olmayan kalmasını sağlayın.

Bir sınıf değişmez olsun ya da olmasın, güvenilmez kaynaklara (unreliable resources) bağımlı bir equals metodu yazmayın. Bu yasağı ihlal ederseniz tutarlılık gereksinimini karşılamak son derece güçtür. Örneğin, java.net.URL'in equals metodu, URL'lerle ilişkilendirilen ana bilgisayarların (hosts) IP adreslerinin karşılaştırılmasına dayanır. Bir ana bilgisayar adını bir IP adresine çevirmek ağ erişimi gerektirebilir ve zamanla aynı sonuçları vermesi garanti değildir. Bu, URL equals metodunun equals sözleşmesini ihlal etmesine neden olabilir ve pratikte sorunlara yol açmıştır. URL'in equals metodunun bu davranışı büyük bir hataydı ve taklit edilmemelidir. Bu tür sorunlardan kaçınmak için equals metotları yalnızca bellekte bulunan (memory-resident) nesneler üzerinde deterministik hesaplamalar gerçekleştirmelidir.

Null-olmama (Non-nullity) — Son gereksinimin resmi bir adı yoktur, bu yüzden onu "null-olmama" (non-nullity) olarak adlandırma özgürlüğünü kullandım. Tüm nesnelerin null'a eşit olmaması gerektiğini söyler. o.equals(null) çağrısına karşılık yanlışlıkla true döndürmeyi hayal etmek zor olsa da, yanlışlıkla NullPointerException fırlatmayı hayal etmek zor değildir. Birçok sınıf, buna karşı açık (explicit) bir null testi ile koruma sağlayan equals metotlarına sahiptir:

Consistency — The fourth requirement says equal objects must remain equal and unequal objects remain unequal for all time. Mutable objects can be equal to different objects at different times, but immutable objects cannot. Whether or not a class is immutable, do not write an equals method that depends on unreliable resources. For example, java.net.URL's equals relies on IP address comparison of hosts which requires network access — a big mistake. To avoid this, equals should perform only deterministic computations on memory-resident objects.

Non-nullity — The final requirement says all objects must be unequal to null. Many classes guard against this with an explicit null test:

// Gereksiz — açık null kontrolü gerekli değil @Override public boolean equals(Object o) { if (o == null) return false; ... }

Bu test gereksizdir. equals metodu, önce argümanını uygun türe dönüştürmek için instanceof operatörünü kullanmalıdır. instanceof operatörü, ilk operandı null ise ikinci operandın türü ne olursa olsun false döndürecek şekilde belirtilmiştir. Bu nedenle, null aktarılırsa tür denetimi false döndürecektir — açık bir null kontrolüne ihtiyaç yoktur:

This test is unnecessary. The instanceof operator returns false if null is passed in, so you don't need an explicit null check:

// Doğru yaklaşım — instanceof null kontrolünü de kapsar @Override public boolean equals(Object o) { if (!(o instanceof MyType)) return false; MyType mt = (MyType) o; ... }

Her şeyi bir araya koyarak, işte yüksek kaliteli bir equals metodu için bir tarif (recipe):

1. Argümanın bu nesneye bir referans olup olmadığını kontrol etmek için == operatörünü kullanın. Öyleyse, true döndürün. Bu yalnızca bir performans optimizasyonudur, ancak karşılaştırma potansiyel olarak pahalıysa yapılmaya değerdir.

2. Argümanın doğru türe sahip olup olmadığını kontrol etmek için instanceof operatörünü kullanın. Değilse, false döndürün.

3. Argümanı doğru türe dönüştürün (cast). Bu dönüştürme bir instanceof testiyle önceden yapıldığından, başarılı olacağı garantidir.

4. Sınıftaki her "anlamlı" (significant) alan için, argümanın ilgili alanının bu nesnenin karşılık gelen alanıyla eşleşip eşleşmediğini kontrol edin. Tüm testler başarılı olursa true döndürün; aksi halde false.

Putting it all together, here's a recipe for a high-quality equals method:

1. Use == to check if the argument is a reference to this object. If so, return true.

2. Use instanceof to check if the argument has the correct type. If not, return false.

3. Cast the argument to the correct type.

4. For each "significant" field, check if it matches the corresponding field of this object.

Tutarlılık & URL Hatası

java.net.URL'in equals metodu, ana bilgisayar adlarını IP adreslerine çevirmeye çalışır — bu ağ gerektiren ve zamanla değişebilen bir işlem. Aynı URL, farklı zamanlarda farklı sonuçlar döndürebilir.

Bu, equals sözleşmesini ihlal eder ve geri uyumluluk nedeniyle düzeltilemez. Java'nın en büyük tasarım hatalarından biridir.

java.net.URL's equals method translates hostnames to IP addresses — a network-dependent, time-varying operation. The same URL may yield different results at different times. This violates the contract and can't be fixed due to backward compatibility.

💡 Kural: equals metotları yalnızca bellekte bulunan nesneler üzerinde deterministik hesaplamalar yapmalıdır. Ağ, dosya sistemi veya diğer dış kaynaklara bağımlı olmayın.

instanceof ile Otomatik Null Kontrolü

JLS 15.20.2'ye göre: null instanceof HerhangiBirTür her zaman false döndürür. Bu nedenle equals metodunuzda ayrı bir if (o == null) return false; kontrolüne gerek yoktur.

instanceof operatörü hem tür kontrolünü hem de null kontrolünü tek satırda yapar; bu daha temiz ve daha az hata eğilimli koddur.

Per JLS 15.20.2: null instanceof AnyType always returns false. So explicit if (o == null) return false; is unnecessary in equals. instanceof handles both type checking and null checking in one shot.
