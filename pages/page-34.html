İlk örneğimiz try-with-resources kullanılarak şöyle görünür:

Here's how our first example looks using try-with-resources:

// try-with-resources — kaynakları kapatmanın en iyi yolu! // try-with-resources - the best way to close resources! static String firstLineOfFile(String path) throws IOException { try (BufferedReader br = new BufferedReader( new FileReader(path))) { return br.readLine(); } }

Ve ikinci örneğimiz try-with-resources ile şöyle görünür:

And here's how our second example looks using try-with-resources:

// Birden fazla kaynakla try-with-resources — kısa ve tatlı // try-with-resources on multiple resources - short and sweet static void copy(String src, String dst) throws IOException { try (InputStream in = new FileInputStream(src); OutputStream out = new FileOutputStream(dst)) { byte[] buf = new byte[BUFFER_SIZE]; int n; while ((n = in.read(buf)) >= 0) out.write(buf, 0, n); } }

try-with-resources sürümleri yalnızca orijinallerinden daha kısa ve daha okunaklı olmakla kalmaz, aynı zamanda çok daha iyi tanılama (diagnostics) sağlar. firstLineOfFile metodunu düşünün. Eğer hem readLine çağrısı hem de (görünmez) close tarafından istisnalar fırlatılırsa, ikinci istisna birincisi lehine bastırılır (suppressed). Aslında, gerçekten görmek istediğiniz istisnayı korumak için birden fazla istisna bastırılabilir. Bu bastırılmış istisnalar (suppressed exceptions) sadece atılıp unutulmaz; yığın izinde (stack trace) bastırıldıklarını belirten bir notla birlikte basılırlar. Ayrıca Java 7'de Throwable'a eklenen getSuppressed metodu ile bunlara programatik olarak erişebilirsiniz.

try-with-resources ifadelerine, tıpkı normal try-finally ifadelerinde olduğu gibi catch cümleleri (catch clauses) koyabilirsiniz. Bu, kodunuzu başka bir iç içe geçme (nesting) katmanıyla kirletmeden istisnaları ele almanıza olanak tanır. Biraz yapmacık (contrived) bir örnek olarak, dosyayı açamazsa veya okuyamazsa istisna fırlatmak yerine döndürülecek bir varsayılan değer (default value) alan firstLineOfFile metodumuzun bir versiyonu:

Not only are the try-with-resources versions shorter and more readable than the originals, but they provide far better diagnostics. Consider the firstLineOfFile method. If exceptions are thrown by both the readLine call and the (invisible) close, the latter exception is suppressed in favor of the former. In fact, multiple exceptions may be suppressed in order to preserve the exception that you actually want to see. These suppressed exceptions are not merely discarded; they are printed in the stack trace with a notation saying that they were suppressed. You can also access them programmatically with the getSuppressed method, which was added to Throwable in Java 7.

You can put catch clauses on try-with-resources statements, just as you can on regular try-finally statements. This allows you to handle exceptions without sullying your code with another layer of nesting. As a slightly contrived example, here's a version our firstLineOfFile method that does not throw exceptions, but takes a default value to return if it can't open the file or read from it:

// catch cümleli try-with-resources // try-with-resources with a catch clause static String firstLineOfFile(String path, String defaultVal) { try (BufferedReader br = new BufferedReader( new FileReader(path))) { return br.readLine(); } catch (IOException e) { return defaultVal; } }

🔍 Kavramlar: 🔍 Concepts:

Bastırılmış İstisnalar (Suppressed Exceptions)

Java 7'de Throwable'a eklenen getSuppressed() metodu, try-with-resources bloğunda close() sırasında fırlatılan istisnaları erişilebilir kılar. Ana istisna korunur; kapatma istisnaları "suppressed" olarak işaretlenir ve yığın izinde ayrıca gösterilir.

The getSuppressed() method added to Throwable in Java 7 makes exceptions thrown during close() in try-with-resources accessible. The primary exception is preserved; close exceptions are marked "suppressed" and shown separately in stack traces.

✅ Programatik erişim

try { // try-with-resources çalıştır } catch (IOException e) { System.out.println("Ana hata: " + e.getMessage()); for (Throwable suppressed : e.getSuppressed()) { System.out.println(" Bastırılmış: " + suppressed.getMessage()); } }

try-with-resources + catch Birleşimi

try-with-resources ifadesi, normal try blokları gibi catch ve hatta finally cümleleri alabilir. catch cümlesi, kaynaklar otomatik kapatıldıktan sonra çalışır. Bu sayede kaynak yönetimi ve hata işleme tek bir temiz yapıda birleşir.

try-with-resources supports catch and even finally clauses, just like regular try. The catch runs after resources are auto-closed, combining resource management and error handling in one clean construct.

💡 catch ekleyerek varsayılan değer döndürme, loglama veya özel istisna fırlatma gibi geri dönüş stratejileri (fallback) zarif bir şekilde uygulanabilir.
