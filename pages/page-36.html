Bölüm 3: Tüm Nesnelere Ortak Metotlar

Chapter 3: Methods Common to All Objects

Object somut (concrete) bir sınıf olmasına rağmen, temel olarak genişletilmek (extension) için tasarlanmıştır. Tüm final olmayan metotları (equals, hashCode, toString, clone ve finalize) açık genel sözleşmelere (explicit general contracts) sahiptir çünkü ezilmek (overridden) üzere tasarlanmışlardır. Bu metotları ezen (overriding) herhangi bir sınıfın, bu genel sözleşmelere uyma sorumluluğu vardır; aksi takdirde, bu sözleşmelere bağımlı olan diğer sınıfların (örneğin HashMap ve HashSet) ilgili sınıfla birlikte düzgün çalışması engellenecektir.

Bu bölüm, Object'in final olmayan metotlarını ne zaman ve nasıl ezeceğinizi anlatır. finalize metodu bu bölümden çıkarılmıştır çünkü Madde 8'de zaten tartışılmıştır. Bir Object metodu olmamakla birlikte, benzer bir karaktere sahip olduğu için Comparable.compareTo de bu bölümde ele alınmaktadır.

Item 10: Obey the general contract when overriding equals

equals metodunu ezmek (overriding) basit görünür, ancak yanlış yapmanın pek çok yolu vardır ve sonuçları korkunç olabilir (dire). Sorunlardan kaçınmanın en kolay yolu, equals metodunu ezmemektir; bu durumda sınıfın her örneği yalnızca kendisine eşit olur. Aşağıdaki koşullardan herhangi biri geçerliyse bu doğru yaklaşımdır:

• Sınıfın her örneği doğası gereği benzersizdir (inherently unique). Bu, değerleri değil aktif varlıkları (active entities) temsil eden Thread gibi sınıflar için geçerlidir. Object tarafından sağlanan equals uygulaması bu sınıflar için tam olarak doğru davranışa sahiptir.

• Sınıfın bir "mantıksal eşitlik" (logical equality) testi sağlamasına gerek yoktur. Örneğin, java.util.regex.Pattern, iki Pattern örneğinin tam olarak aynı düzenli ifadeyi (regular expression) temsil edip etmediğini kontrol etmek için equals'ı ezebilirdi; ancak tasarımcılar istemcilerin bu işlevselliğe ihtiyaç duyacağını veya isteyeceğini düşünmedi. Chapter 3: Methods Common to All Objects

Although Object is a concrete class, it is designed primarily for extension. All of its nonfinal methods (equals, hashCode, toString, clone, and finalize) have explicit general contracts because they are designed to be overridden. It is the responsibility of any class overriding these methods to obey their general contracts; failure to do so will prevent other classes that depend on the contracts (such as HashMap and HashSet) from functioning properly in conjunction with the class.

This chapter tells you when and how to override the nonfinal Object methods. The finalize method is omitted from this chapter because it was discussed in Item 8. While not an Object method, Comparable.compareTo is discussed in this chapter because it has a similar character.

Item 10: Obey the general contract when overriding equals

Overriding the equals method seems simple, but there are many ways to get it wrong, and consequences can be dire. The easiest way to avoid problems is not to override the equals method, in which case each instance of the class is equal only to itself. This is the right thing to do if any of the following conditions apply:

• Each instance of the class is inherently unique. This is true for classes such as Thread that represent active entities rather than values. The equals implementation provided by Object has exactly the right behavior for these classes.

• There is no need for the class to provide a "logical equality" test. For example, java.util.regex.Pattern could have overridden equals to check whether two Pattern instances represented exactly the same regular expression, but the designers didn't think that clients would need or want this functionality. Genel Sözleşme (General Contract)

Object sınıfının equals, hashCode, toString, clone gibi metotları, tüm alt sınıfların uyması beklenen genel sözleşmeler (general contracts) tanımlar. Bu sözleşmeler, Java koleksiyonları (HashMap, HashSet, TreeMap vb.) gibi altyapı sınıflarının doğru çalışmasının temelidir.

Sözleşmeyi ihlal etmek, koleksiyonların sessizce yanlış sonuçlar üretmesine veya çökmesine neden olabilir.

Object's methods like equals, hashCode, toString, clone define general contracts that all subclasses are expected to obey. These contracts are the foundation for infrastructure classes like Java collections (HashMap, HashSet, TreeMap, etc.).

Violating the contract can cause collections to silently produce wrong results or crash.

💡 equals ve hashCode arasında altın kural: Eğer a.equals(b) ise, a.hashCode() == b.hashCode() olmalıdır. Tersi zorunlu değildir.

Mantıksal Eşitlik (Logical Equality)

Nesne kimliği (identity) vs mantıksal eşitlik (equality):

• == operatörü: İki referansın aynı nesneye mi işaret ettiğini kontrol eder (kimlik).

• equals(): İki nesnenin mantıksal olarak eşdeğer olup olmadığını kontrol eder (eşitlik).

Integer ve String gibi değer sınıfları (value classes), programcının iki farklı nesnenin aynı değeri temsil edip etmediğini bilmek istediği sınıflardır. Bu sınıflar equals'ı ezmelidir.

Object identity vs logical equality:

• ==: Checks if two references point to the same object (identity).

• equals(): Checks if two objects are logically equivalent (equality).

Value classes like Integer and String are cases where programmers want to know if two distinct objects represent the same value. These classes must override equals.
