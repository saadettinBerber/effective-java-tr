Madde 53: Varargs'ı Dikkatli Kullanın

Item 53: Use varargs judiciously

Varargs bir veya daha fazla argüman gerektiğinde, ilk parametreyi ayrı bildirin:

When one or more args required, declare the first separately:

// Doğru — en az 1 argüman garantili static int min(int firstArg, int... remainingArgs) { ... }

Performans açısından kritik olan durumlarda 0-3 parametreli aşırı yüklemeler sağlayıp, sadece 4+ için varargs kullanın (EnumSet'in stratejisi).

Madde 54: Null Yerine Boş Koleksiyonlar veya Diziler Döndürün

Item 54: Return empty collections or arrays, not nulls

Asla null döndürmeyin! Boş bir koleksiyon veya dizi döndürmek istemciyi null kontrolü yapmak zorunda bırakmaz. Collections.emptyList(), Collections.emptySet(), Collections.emptyMap() ve sıfır uzunluklu diziler (new String[0]) kullanın — bunlar değişmezdir ve paylaşılabilir.

Madde 55: Optional'ı Dikkatli Döndürün

Item 55: Return optionals judiciously

Java 8'de Optional<T> eklendi — bir değer içerebilen veya boş olabilen değişmez bir kapsayıcı. Sonuç döndüreneyebilecek metotlar için null veya istisna yerine Optional döndürmeyi düşünün.

Kurallar: Koleksiyonlar, stream'ler, diziler veya ilkel türler için Optional kullanmayın — bunların kendi boş temsilleri var. Optional'ı alan, koleksiyon değeri veya harita anahtarı/değeri olarak kullanmayın. İlkel türler için OptionalInt, OptionalLong, OptionalDouble kullanın.

Madde 56: Tüm Dışa Açık API Elemanları İçin Javadoc Yazın

Item 56: Write doc comments for all exposed API elements

API'nizi düzgün belgelemek için: her dışa açık sınıf, arayüz, yapıcı, metot ve alan bildiriminden önce bir belge yorumu koyun. Her metodun ne yaptığını, ön koşulları (@throws), son koşulları ve yan etkileri belgelendirin. İlk cümle özet açıklama (summary description) olmalıdır.

Önemli etiketler: @param, @return, @throws, {@code}, {@literal}, {@index} (Java 9), @implSpec.
