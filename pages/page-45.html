Önceki tarife göre oluşturulmuş bir equals metodu, bu basitleştirilmiş PhoneNumber sınıfında gösterilmiştir:

An equals method constructed according to the previous recipe is shown in this simplistic PhoneNumber class:

// Tipik bir equals metoduna sahip sınıf public final class PhoneNumber { private final short areaCode, prefix, lineNum; public PhoneNumber(int areaCode, int prefix, int lineNum) { this.areaCode = rangeCheck(areaCode, 999, "area code"); this.prefix = rangeCheck(prefix, 999, "prefix"); this.lineNum = rangeCheck(lineNum, 9999, "line num"); } private static short rangeCheck(int val, int max, String arg) { if (val < 0 || val > max) throw new IllegalArgumentException(arg + ": " + val); return (short) val; } @Override public boolean equals(Object o) { if (o == this) // 1. Referans kontrolü return true; if (!(o instanceof PhoneNumber)) // 2. Tür kontrolü return false; PhoneNumber pn = (PhoneNumber) o; // 3. Dönüştürme return pn.lineNum == lineNum // 4. Alan karşılaştırma && pn.prefix == prefix && pn.areaCode == areaCode; } ... // Kalan kısım çıkarıldı }

İşte birkaç son uyarı (caveats):

• equals'ı ezdiğinizde hashCode'u da her zaman ezin (Madde 11).

• Çok akıllı olmaya çalışmayın. Alanları basitçe eşitlik için test ederseniz, equals sözleşmesine uymak zor değildir. Eşdeğerlik arayışında aşırı agresif olursanız, başınız belaya girer. Herhangi bir takma ad (aliasing) biçimini hesaba katmak genellikle kötü bir fikirdir. Örneğin, File sınıfı aynı dosyaya atıfta bulunan sembolik bağlantıları eşitlemeye çalışmamalıdır. Neyse ki çalışmıyor.

• equals bildiriminde (declaration) Object yerine başka bir tür kullanmayın. Programcıların şöyle görünen bir equals metodu yazması alışılmadık değildir:

Here are a few final caveats:

• Always override hashCode when you override equals (Item 11).

• Don't try to be too clever. If you simply test fields for equality, it's not hard to adhere to the contract. Don't take aliasing into account.

• Don't substitute another type for Object in the equals declaration.

// YanlıŞ — parametre türü Object olmalı! public boolean equals(MyClass o) { ... }

Bu metot Object.equals'ı ezmez (override), aksine aşırı yükler (overload). @Override anotasyonunu tutarlı bir şekilde kullanarak bu hatadan kaçınabilirsiniz (Madde 40); bu equals metodu derlenmeyecektir:

This method does not override Object.equals; it overloads it instead. You can avoid this error by using the @Override annotation consistently (Item 40); this equals method won't compile:

// Derlenemez! — doğru şekilde hata yakalar @Override public boolean equals(MyClass o) { ... }

🔍 Kavramlar: 🔍 Concepts:

Override vs Overload Tuzağı

equals(MyClass o) yazmak Object.equals(Object o)'yu ezmez (override), yalnızca aşırı yükler (overload). Koleksiyonlar ve framework'ler hâlâ Object.equals'ı çağıracağından, sizin metodunuz hiç çalışmaz!

Çözüm: Her zaman @Override anotasyonunu kullanın. Derleyici yanlış imzayı (signature) tespit edecektir.

equals(MyClass o) overloads rather than overrides Object.equals(Object o). Collections will call the original, so yours never runs!

Fix: Always use @Override. The compiler will catch the wrong signature.

AutoValue

Google'ın açık kaynak AutoValue kütüphanesi, equals, hashCode ve toString metotlarını sınıfın alanlarına bakarak otomatik üretir. Doğru ve tutarlı uygulamalar sağlar; böylece elle yazma hataları elimine edilir.

IDE'ler de equals ve hashCode üretebilir; ancak AutoValue, kaynak kod değişikliklerinde otomatik güncelleme yapması açısından daha güvenilirdir.

Google's open-source AutoValue generates equals, hashCode, and toString automatically from class fields. Eliminates hand-coding errors. IDEs can also generate these, but AutoValue auto-updates when fields change.
