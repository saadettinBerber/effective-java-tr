Chapter 4 — Item 17: Değişmezlik Özet
↩ Önceki sayfadan devam — Madde 17: Değişmezlik dezavantajları, çözüm stratejileri ve özet

4. Değişmez nesneler harika yapı taşlarıdır. İster diğer nesnelerin bileşenleri ister Map anahtarları veya Set elemanları olsun — hiç değişmeyeceklerini bildiğiniz için durumun bozulması konusunda endişelenmenize gerek yoktur.

5. Atomik hata güvenliği (failure atomicity) sağlarlar. Durumları asla değişmez, bu nedenle geçici tutarsızlık olasılığı yoktur.

Değişmez sınıfların ana dezavantajı, her farklı değer için ayrı bir nesne gerektirmeleridir. Bu nesnelerin oluşturulması maliyetli olabilir, özellikle büyük nesneler söz konusuysa. Örneğin, milyonlarca bitlik bir BigInteger'ın tek bir bitini değiştirmek istiyorsanız:

4) Great building blocks for maps/sets. 5) Failure atomicity for free. Main disadvantage: every distinct value requires a separate object — expensive for large objects.

BigInteger moby = ...; moby = moby.flipBit(0); // Yeni milyonlarca bitlik nesne oluşturur!

İki çözüm stratejisi vardır: (1) Sık kullanılan çok adımlı işlemler için bir değişebilir eşlik sınıfı (companion class) sağlayın — String için StringBuilder gibi. (2) Değişmez sınıfları final yerine özel yapıcılarla kapatın — bu, statik fabrika metotları aracılığıyla önbellekleme esnekliği verir.

Two strategies: (1) Provide a mutable companion class (like StringBuilder for String). (2) Use private constructors with static factories instead of making the class final.

// final yerine özel yapıcılarla değişmezlik public class Complex { private final double re; private final double im; private Complex(double re, double im) { this.re = re; this.im = im; } public static Complex valueOf(double re, double im) { return new Complex(re, im); } ... }
Madde 17 — Özet: Sınıfları değişmez yapmak için küçük bir çaba harcayın. Sınıfı değişmez yapamıyorsanız, mümkün olduğunca değişmezliğini sınırlayın. Her alanı private final yapın — mutlak bir nedeni olmadıkça. Yapıcılar, tüm değişmezleri belirlenmiş, tamamen başlatılmış nesneler oluşturmalıdır. Geçerli bir neden olmadan "yeniden başlatma" metotları eklemeyin — karmaşıklık yaratır ama performans kazancı sağlamaz. CountDownLatch sınıfı bu ilkeyi somutlaştırır: değişebilirdir ama durum alanı küçüktür ve örnek yaratılınca yalnızca bir geçiş yapılabilir — sayaç sıfıra ulaştığında latch bir daha kullanılamaz.
Item 17 — Summary: Make classes immutable when possible. Limit mutability. Make every field private final. Constructors should create fully initialized objects with all invariants established.

Değişebilir Eşlik Sınıfı

Değişmez sınıflar pahalı çok adımlı işlemler için bir değişebilir eşlik sınıfı sağlayabilir:

• String → StringBuilder (veya StringBuffer)
• BigInteger → MutableBigInteger (paket-özel)

İstemci hangi çok adımlı işlemleri yapacağını önceden tahmin edebiliyorsanız, eşlik sınıfını paket-özel tutup iç optimizasyonlarda kullanabilirsiniz.

Mutable companion classes like StringBuilder for String handle multi-step operations efficiently. Can be package-private for internal optimization.
