Chapter 2 — Item 8: Sonlandırıcılardan ve Temizleyicilerden Kaçının / Avoid finalizers and cleaners
↩ Önceki sayfadan devam — Madde 8: Native peer ve Cleaner kullanımı

Temizleyicilerin ikinci meşru (legitimate) kullanım alanı, doğal eşdüzey nesnelerle (native peers) ilgilidir. Doğal eşdüzey nesne (native peer), normal bir nesnenin doğal metotlar (native methods) aracılığıyla yetki devrettiği (delegates) doğal (Java-dışı) bir nesnedir. Doğal eşdüzey nesne normal bir nesne olmadığından, Çöp Toplayıcı onun hakkında bilgi sahibi değildir ve Java eşdüzeyi (Java peer) geri alındığında onu geri alamaz. Bu görev için, performans kabul edilebilir olduğu ve doğal eşdüzey nesne kritik kaynaklar (critical resources) taşımadığı varsayımıyla, bir temizleyici veya sonlandırıcı uygun bir araç (vehicle) olabilir. Performans kabul edilemezse veya doğal eşdüzey nesne derhal geri alınması gereken kaynaklar taşıyorsa, sınıfın daha önce anlatıldığı gibi bir close metodu olmalıdır.

Temizleyicilerin kullanımı biraz çetrefillidir (tricky). Aşağıda, olanağı gösteren basit bir Room sınıfı yer almaktadır. Odaların, geri alınmadan önce temizlenmesi (cleaned) gerektiğini varsayalım. Room sınıfı AutoCloseable arayüzünü uygular; otomatik temizleme güvenlik ağının bir temizleyici kullanması salt bir uygulama detayıdır (implementation detail). Sonlandırıcıların aksine, temizleyiciler bir sınıfın kamusal API'sini (public API) kirletmez:

A second legitimate use of cleaners concerns objects with native peers. A native peer is a native (non-Java) object to which a normal object delegates via native methods. Because a native peer is not a normal object, the garbage collector doesn't know about it and can't reclaim it when its Java peer is reclaimed. A cleaner or finalizer may be an appropriate vehicle for this task, assuming the performance is acceptable and the native peer holds no critical resources. If the performance is unacceptable or the native peer holds resources that must be reclaimed promptly, the class should have a close method, as described earlier.

Cleaners are a bit tricky to use. Below is a simple Room class demonstrating the facility. Let's assume that rooms must be cleaned before they are reclaimed. The Room class implements AutoCloseable; the fact that its automatic cleaning safety net uses a cleaner is merely an implementation detail. Unlike finalizers, cleaners do not pollute a class's public API:

// Güvenlik ağı olarak cleaner kullanan AutoCloseable sınıf // An autocloseable class using a cleaner as a safety net public class Room implements AutoCloseable { private static final Cleaner cleaner = Cleaner.create(); // Temizleme gerektiren kaynak. Room'a referans vermemeli! // Resource that requires cleaning. Must not refer to Room! private static class State implements Runnable { int numJunkPiles; // Bu odadaki çöp yığını sayısı State(int numJunkPiles) { this.numJunkPiles = numJunkPiles; } // close metodu veya cleaner tarafından çağrılır @Override public void run() { System.out.println("Cleaning room"); numJunkPiles = 0; } } // Bu odanın durumu, cleanable ile paylaşılır private final State state; // Cleanable'ımız. Oda GC'ye uygun olduğunda odayı temizler private final Cleaner.Cleanable cleanable; public Room(int numJunkPiles) { state = new State(numJunkPiles); cleanable = cleaner.register(this, state); } @Override public void close() { cleanable.clean(); } }

Statik iç içe sınıf (static nested class) State, temizleyicinin odayı temizlemesi için gereken kaynakları tutar. Bu durumda, bu basitçe odadaki karmaşıklık miktarını temsil eden numJunkPiles alanıdır. Daha gerçekçi bir senaryoda, doğal bir eşdüzey nesneye (native peer) işaret eden bir final long olabilirdi. State, Runnable arayüzünü uygular ve run metodu, Room yapıcısında State örneğimizi temizleyicimizle kaydettiğimizde (register) elde ettiğimiz Cleanable tarafından en fazla bir kez çağrılır. run metodunun çağrılması iki şeyden biri tarafından tetiklenir: Genellikle Room'un close metodunun Cleanable'ın clean metodunu çağırmasıyla tetiklenir. İstemci, bir Room örneği çöp toplamaya uygun hale gelene kadar close metodunu çağırmazsa, temizleyici (umarız ki) State'in run metodunu çağıracaktır.

Kritik bir nokta: Bir State örneğinin kendi Room örneğine referans vermemesi hayati önem taşır. Eğer verseydi, Room örneğinin çöp toplamaya uygun hale gelmesini (ve otomatik temizlenmesini) engelleyecek bir döngüsellik (circularity) yaratırdı. Bu nedenle State, iç içe olmayan sınıflar (nonstatic nested classes) kapsayan örneklerine (enclosing instances) referans içerdiğinden (Madde 24), statik bir iç içe sınıf olmalıdır. Aynı şekilde, kapsayan nesnelere referans yakalayabilecekleri (capture) için lambda kullanmak da tavsiye edilmez.

The static nested State class holds the resources required by the cleaner to clean the room. In this case, it is simply the numJunkPiles field. More realistically, it might be a final long containing a pointer to a native peer. State implements Runnable, and its run method is called at most once by the Cleanable we get when we register our State instance with our cleaner in the Room constructor. The call to the run method will be triggered by one of two things: Usually by Room's close method calling Cleanable's clean method. If the client fails to call the close method by the time a Room instance is eligible for garbage collection, the cleaner will (hopefully) call State's run method.

It is critical that a State instance does not refer to its Room instance. If it did, it would create a circularity that would prevent the Room instance from becoming eligible for garbage collection (and from being automatically cleaned). Therefore, State must be a static nested class because nonstatic nested classes contain references to their enclosing instances (Item 24). It is similarly inadvisable to use a lambda because they can easily capture references to enclosing objects.

🔍 Kavramlar: 🔍 Concepts:

Native Peer (Doğal Eşdüzey Nesne)

Native peer, Java nesnesinin JNI (Java Native Interface) aracılığıyla yetki devrettiği (delegates) Java-dışı (C/C++) bir nesnedir. Java'nın Çöp Toplayıcısı yalnızca Java yığınını (heap) yönetir; doğal belleği (native memory) göremez. Java nesnesi geri alındığında, bağlı native peer otomatik olarak temizlenmez.

Örnekler: OpenGL texture handle'ları, DirectX buffer'ları, JNI ile ayrılmış C yapıları.

A native peer is a non-Java (C/C++) object that a Java object delegates to via JNI. Java's GC only manages the Java heap; it can't see native memory. When the Java object is reclaimed, the associated native peer isn't automatically cleaned.

Examples: OpenGL texture handles, DirectX buffers, C structs allocated via JNI.

💡 Kritik kaynaklar (dosya tanımlayıcıları, soketler) tutan native peer'lar için close() metodu şarttır. Cleaner yalnızca kritik olmayan (örneğin salt bellek) kaynaklar için güvenlik ağı olarak kullanılmalıdır.

Döngüsel Referans (Circular Reference) Tuzağı

Cleaner'ın temizleme eylemi (cleaning action) olan State nesnesi, temizlenecek Room nesnesine geri referans verirse ne olur? Döngüsel referans oluşur: Room → Cleanable → State → Room. GC, Room'u erişilemez olarak işaretleyemez çünkü State hâlâ ona referans tutuyor. Sonuç: Room asla temizlenemez ve bellek sızıntısı oluşur.

If the State (cleaning action) holds a back-reference to Room, a cycle forms: Room → Cleanable → State → Room. GC can't mark Room as unreachable because State still points to it. Result: Room never gets cleaned — memory leak.

💡 Temizleme eylemi olarak kullanılan iç sınıf mutlaka static olmalıdır. Lambda yerine statik iç sınıf tercih edin; lambda'lar kapsayan nesneye gizli referans yakalayabilir.

Statik vs Non-Statik İç Sınıf

Non-statik iç sınıf (inner class): Kapsayan sınıfın örneğine gizli bir referans (Outer.this) tutar. Bu referans, kapsayan nesneyi GC'ye karşı canlı tutar.

Statik iç sınıf (static nested class): Kapsayan sınıfa bağımlılığı yoktur; bağımsız bir sınıf gibi davranır. GC açısından güvenlidir.

Non-static inner class: Holds an implicit reference to the enclosing instance (Outer.this). This keeps the outer object alive for GC.

Static nested class: No dependency on the enclosing class; behaves like an independent class. GC-safe.

❌ Non-statik — gizli referans tutar

public class Outer { class Inner { // Gizlice Outer.this referansı tutar! } }

✅ Statik — bağımsız

public class Outer { static class Nested { // Outer'a referans yok, GC güvenli } }
💡 Madde 24'te detaylandırılacağı gibi: Eğer bir iç sınıfın kapsayan nesneye erişmesi gerekmiyorsa, her zaman static yapın. Bu hem bellek sızıntılarını önler hem de performansı artırır.
