Chapter 2 — Item 2: Çok Sayıda Parametreyle Karşılaşıldığında Builder'ı Düşünün / Consider a builder when faced with many constructor parameters
↩ Önceki sayfadan devam — NyPizza ve Calzone hiyerarşik builder sınıfları tamamlanıyor.
// NyPizza kurucusu (önceki sayfadan devam) private NyPizza(Builder builder) { super(builder); size = builder.size; } } public class Calzone extends Pizza { private final boolean sauceInside; public static class Builder extends Pizza.Builder<Builder> { private boolean sauceInside = false; // Varsayılan public Builder sauceInside() { sauceInside = true; return this; } @Override public Calzone build() { return new Calzone(this); } @Override protected Builder self() { return this; } } private Calzone(Builder builder) { super(builder); sauceInside = builder.sauceInside; } }

Her alt sınıfın builder'ındaki build() metodu, doğru alt sınıfı döndürecek şekilde bildirilmiştir: NyPizza.Builder'ın build() metodu NyPizza döndürürken Calzone.Builder'ınki Calzone döndürür. Bir alt sınıf metodunun üst sınıfta bildirilen dönüş tipinin alt tipini döndürecek şekilde tanımlanması tekniğine kovaryant dönüş tipi belirleme (covariant return typing) adı verilir. Bu teknik sayesinde istemciler tip dönüşümüne (cast) gerek kalmadan bu builder'ları kullanabilir.

Bu "hiyerarşik builder'lar" için istemci kodu, basit NutritionFacts builder'ı için yazılan kodla neredeyse aynıdır. Aşağıdaki örnek kısalık olsun diye enum sabitlerinde statik import kullandığını varsaymaktadır:

Note that the build method in each subclass's builder is declared to return the correct subclass: the build method of NyPizza.Builder returns NyPizza, while the one in Calzone.Builder returns Calzone. This technique, wherein a subclass method is declared to return a subtype of the return type declared in the super-class, is known as covariant return typing. It allows clients to use these builders without the need for casting.

The client code for these "hierarchical builders" is essentially identical to the code for the simple NutritionFacts builder. The example client code shown next assumes static imports on enum constants for brevity:

// Hiyerarşik builder'lar için istemci kodu NyPizza pizza = new NyPizza.Builder(SMALL) .addTopping(SAUSAGE).addTopping(ONION).build(); Calzone calzone = new Calzone.Builder() .addTopping(HAM).sauceInside().build();
Kovaryant dönüş tipi belirleme neden önemlidir?
NyPizza.Builder.build()'ın dönüş tipi NyPizza'dır; üst sınıftaki Pizza değil. Bu sayede istemci sonucu cast etmeden doğrudan NyPizza değişkenine atayabilir. Hem daha güvenli hem de daha okunabilir bir koddur.
Why does covariant return typing matter?
NyPizza.Builder.build() returns NyPizza, not the supertype Pizza. This lets clients assign the result directly to a NyPizza variable without an explicit cast — making the code both safer and more readable.

Builder'ların yapıcı metotlara karşı küçük bir avantajı, builder'ların birden fazla değişken argümanlı (varargs) parametreye sahip olabilmesidir; çünkü her parametre kendi ayrı metodunda belirtilir. Bunun yanı sıra builder'lar, bir metoda yapılan birden fazla çağrıda iletilen parametreleri tek bir alanda toplayabilir — daha önce gösterilen addTopping metodunda olduğu gibi.

A minor advantage of builders over constructors is that builders can have multiple varargs parameters because each parameter is specified in its own method. Alternatively, builders can aggregate the parameters passed into multiple calls to a method into a single field, as demonstrated in the addTopping method earlier.

Kovaryant Dönüş Tipi / Covariant Return Typing

Kovaryant dönüş tipi belirleme, bir alt sınıf metodunun üst sınıftaki metoddan daha spesifik bir dönüş tipi bildirmesine olanak tanır. Builder hiyerarşilerinde her alt sınıfın build() metodu kendi somut tipini döndürür; istemci cast gerekmez.

Covariant return typing lets a subclass method declare a more specific return type than the superclass method. In builder hierarchies, each subclass's build() returns its own concrete type, so clients need no casts.

✗ KÖTÜ — Cast gerekli
abstract class VehicleBuilder { abstract Vehicle build(); // Genel tip döndürüyor } class TruckBuilder extends VehicleBuilder { @Override public Vehicle build() { return new Truck(this); } } Truck t = (Truck) new TruckBuilder().build(); // Cast!
✓ İYİ — Kovaryant dönüş, cast yok
class TruckBuilder extends VehicleBuilder { @Override public Truck build() { // Truck döndürüyor — kovaryant! return new Truck(this); } } Truck t = new TruckBuilder().load(5000).build(); // Temiz
💡 Her alt sınıf builder'ında @Override build() metodunu kendi somut tipini döndürecek şekilde tanımlayın. Bu, Java'nın tip sistemiyle uyumlu, güvenli ve okunabilir bir API sağlar.
💡 Always override build() in each concrete subclass builder to return the concrete type. This yields a type-safe, readable API that leverages Java's type system.

Hiyerarşik Builder / Hierarchical Builder

Hiyerarşik builder'lar, sınıf hiyerarşisini birebir yansıtan builder hiyerarşileri oluşturur. Her alt sınıf builder'ı, üst sınıf builder'ını genişletir. Ortak parametreler üst sınıfta, özgül parametreler alt sınıfta tanımlanır. Bu sayede kod tekrarı önlenir ve her alt sınıfa özel parametreler tip-güvenli biçimde desteklenir.

Hierarchical builders mirror the class hierarchy in the builder hierarchy. Each subclass builder extends the parent builder. Common parameters live in the parent, subclass-specific ones in the child. This eliminates code duplication and supports type-safe subclass-specific parameters.

✗ KÖTÜ — Tekrarlı, bağımsız builder'lar
class CarBuilder { private String color; private int seats; public CarBuilder color(String c) { color = c; return this; } public Car build() { return new Car(color, seats); } } class ElectricCarBuilder { // color mantığı kopyalandı! private String color; private int batteryKwh; public ElectricCarBuilder color(String c) { color = c; return this; } public ElectricCar build() { return new ElectricCar(color, batteryKwh); } }
✓ İYİ — Hiyerarşik builder
abstract class VehicleBuilder<T extends VehicleBuilder<T>> { private String color; public T color(String c) { color = c; return self(); } abstract Vehicle build(); protected abstract T self(); } class ElectricCarBuilder extends VehicleBuilder<ElectricCarBuilder> { private int batteryKwh; public ElectricCarBuilder batteryKwh(int b) { batteryKwh = b; return this; } @Override public ElectricCar build() { return new ElectricCar(this); } @Override protected ElectricCarBuilder self() { return this; } } ElectricCar car = new ElectricCarBuilder().color("blue").batteryKwh(75).build();
💡 Sınıf hiyerarşiniz büyüdükçe hiyerarşik builder, ortak alanları üst sınıfta toplar ve her alt sınıf yalnızca kendine özgü parametreleri ekler.
💡 As your class hierarchy grows, hierarchical builders centralize common fields in the parent builder while each subclass adds only its own specific parameters.

Builder & Çoklu Parametreler / Builder with Multiple Parameters

Yapıcı metotlarda yalnızca son parametre varargs olabilir. Birden fazla liste-türü parametre gerektiğinde yapıcılar yetersiz kalır. Builder'lar her parametreyi ayrı metodda tanımladığı için bu kısıtlamadan kurtulur ve aynı metot birden fazla kez çağrılarak değerler biriktirilir.

Constructors allow at most one varargs parameter, always at the end. When you need multiple list-type parameters, constructors fall short. Builders solve this by defining each parameter in its own method, allowing the same method to be called multiple times to accumulate values.

✗ KÖTÜ — Yapıcıda birden fazla varargs olamaz
// Derleme hatası: iki varargs parametresi olamaz public Report(String... sections, String... authors) { ... } // Geçici çözüm: List kullanmak zorunda kalıyoruz — okunaksız public Report(List<String> sections, List<String> authors) { ... } new Report(List.of("Intro", "Body"), List.of("Alice", "Bob"));
✓ İYİ — Builder ile çoklu biriktirme
class Report { static class Builder { private final List<String> sections = new ArrayList<>(); private final List<String> authors = new ArrayList<>(); public Builder addSection(String s) { sections.add(s); return this; } public Builder addAuthor(String a) { authors.add(a); return this; } public Report build() { return new Report(this); } } } Report r = new Report.Builder() .addSection("Giriş").addSection("Sonuç") .addAuthor("Alice").addAuthor("Bob") .build();
💡 Aynı addX() metodunu birden fazla kez çağırarak değerleri biriktirme tekniği, Builder kalıbının en etkileyici özelliklerinden biridir — özellikle topping/tag/permission gibi koleksiyon parametreleri için idealdir.
💡 Calling the same addX() method multiple times to accumulate values is one of the most powerful features of the Builder pattern — especially for collection parameters like toppings, tags, or permissions.
