Item 2: Consider a builder when faced with many constructor parameters Madde 2: Çok Sayıda Parametreyle Karşılaşınca Builder'ı Düşünün
↩ Önceki sayfadan devam: JavaBeans kalıbının tutarsız durum (inconsistent state) problemi anlatılıyordu. ↩ Continued from previous page: The JavaBeans pattern's inconsistent state problem was being discussed.

…kalıbı, bir sınıfın değiştirilemez (immutable) yapılmasının önünü kapatır (Madde 17) ve programcının iş parçacığı güvenliğini (thread safety) sağlamak için ek çaba harcamasını zorunlu kılar.

…pattern precludes the possibility of making a class immutable (Item 17) and requires added effort on the part of the programmer to ensure thread safety.

Nesnenin oluşturulması tamamlandığında onu manuel olarak "dondurarak (freezing)" ve donmadan önce kullanılmasına izin vermeyerek bu dezavantajları azaltmak mümkündür; ancak bu varyant kullanışsız (unwieldy) olup pratikte neredeyse hiç kullanılmaz. Üstelik programcının freeze metodunu nesnede çağırıp çağırmadığını derleyici garanti edemediğinden çalışma zamanında hatalara yol açabilir.

It is possible to reduce these disadvantages by manually "freezing" the object when its construction is complete and not allowing it to be used until frozen, but this variant is unwieldy and rarely used in practice. Moreover, it can cause errors at runtime because the compiler cannot ensure that the programmer calls the freeze method on an object before using it.

Neyse ki üçüncü bir alternatif daha var: Teleskopik yapıcı kalıbının güvenliğini JavaBeans kalıbının okunabilirliğiyle birleştiren bu alternatif, Builder kalıbıdır (Builder pattern) [Gamma95]. İstemci (client) istenen nesneyi doğrudan oluşturmak yerine, önce tüm zorunlu parametrelerle bir yapıcı metot (veya statik fabrika) çağırarak bir builder nesnesi elde eder. Ardından builder üzerinde setter benzeri metotlar çağırarak istenen opsiyonel parametreleri ayarlar. Son olarak parametresiz bir build() metodu çağırarak, genellikle değiştirilemez olan asıl nesneyi üretir. Builder genellikle oluşturduğu sınıfın statik üye sınıfıdır (static member class) (Madde 24). Luckily, there is a third alternative that combines the safety of the telescoping constructor pattern with the readability of the JavaBeans pattern. It is a form of the Builder pattern [Gamma95]. Instead of making the desired object directly, the client calls a constructor (or static factory) with all of the required parameters and gets a builder object. Then the client calls setter-like methods on the builder object to set each optional parameter of interest. Finally, the client calls a parameterless build method to generate the object, which is typically immutable. The builder is typically a static member class of the class it builds (Item 24).

Builder Kalıbı (Builder Pattern) Builder Pattern
Karmaşık nesneleri adım adım, okunaklı biçimde oluşturma kalıbı Pattern for constructing complex objects step by step with readability
Builder kalıbı, çok sayıda (özellikle opsiyonel) parametresi olan nesneleri oluşturmak için kullanılır. Zorunlu parametreler Builder'ın yapıcısına, opsiyoneller ise adlandırılmış setter metotlarına taşınır. build() çağrısıyla nesne bir kez ve geçerli hâlde oluşturulur. The Builder pattern is used to construct objects with many (especially optional) parameters. Required parameters go in the Builder's constructor; optional ones in named setter methods. Calling build() creates the object once, in a valid state.
✗ Kötü (çok fazla parametreli yapıcı) 
// Kötü: Hangi parametre ne anlama geliyor?
HttpRequest req = new HttpRequest(
    "GET", "/api/users", null, 30, true, false, 3
);
7 parametreli yapıcı: okunaksız, hataya açık, null değerlerin anlamı belirsiz. 7-parameter constructor: unreadable, error-prone, null values have unclear meaning.
✓ İyi (Builder ile) 
// İyi: Her parametre adıyla açıkça belirtiliyor
HttpRequest req = new HttpRequest.Builder("GET", "/api/users")
    .timeout(30)
    .followRedirects(true)
    .retries(3)
    .build();
Zorunlu parametreler (method, path) Builder yapıcısında; opsiyoneller adlandırılmış metotlarda. Kod kendi kendini açıklıyor. Required params (method, path) in Builder constructor; optionals in named methods. Code is self-documenting.
💡 İpucu: Builder kalıbını şu durumlarda kullanın: 4+ parametre varsa, parametrelerin birçoğu opsiyonelse veya nesnenin değiştirilemez (immutable) olması gerekiyorsa. 💡 Tip: Use the Builder pattern when: you have 4+ parameters, many are optional, or the object needs to be immutable.
Değiştirilemezlik (Immutability) Immutability
Oluşturulduktan sonra durumu değiştirilemeyen nesne tasarımı Object design where state cannot change after creation
Değiştirilemez nesneler iş parçacığı güvenlidir (thread-safe), önbelleğe alınabilir ve paylaşılabilir. JavaBeans kalıbı setter metotları gerektirdiğinden sınıfı değiştirilemez yapmayı engeller. Builder kalıbında ise nesne tek bir build() çağrısıyla, tüm alanlar final olarak oluşturulabilir. Immutable objects are thread-safe, cacheable, and shareable. The JavaBeans pattern requires setter methods, which prevents immutability. With the Builder pattern, the object can be created in one build() call with all fields declared final.
✗ Kötü (değiştirilebilir, thread-safe değil) 
// Kötü: Setter metotlar ile değiştirilebilir durum
public class Coordinate {
    private double lat, lon; // final değil!
    public void setLat(double v) { lat = v; }
    public void setLon(double v) { lon = v; }
}
// İki thread aynı anda setLat ve setLon çağırabilir!
Alanlar final değil, setter metotlarla değiştirilebiliyor. Çok iş parçacıklı ortamda tehlikeli. Fields are not final, can be mutated via setters. Dangerous in multi-threaded environments.
✓ İyi (değiştirilemez, thread-safe) 
// İyi: final alanlar, Builder ile oluşturuluyor
public final class Coordinate {
    private final double lat;
    private final double lon;

    private Coordinate(Builder b) {
        this.lat = b.lat;
        this.lon = b.lon;
    }

    public static class Builder {
        private double lat, lon;
        public Builder lat(double v) { lat = v; return this; }
        public Builder lon(double v) { lon = v; return this; }
        public Coordinate build() { return new Coordinate(this); }
    }
}
Sınıf hem final (alt sınıf oluşturulamaz) hem de alanlar final (değiştirilemez). İş parçacığı güvenlidir, önbelleğe alınabilir. Class is both final (no subclassing) and fields are final (no mutation). Thread-safe and cacheable.
💡 İpucu: Değiştirilemez sınıflar hakkında daha fazla bilgi için Madde 17'ye bakın: "Değiştirilebilirliği En Aza İndirin". 💡 Tip: For more on immutable classes, see Item 17: "Minimize Mutability".
Akıcı API (Fluent API) / Metot Zincirleme Fluent API / Method Chaining
Metotların this döndürerek zincirlenmesi Methods returning this to enable chaining
Builder setter metotları this (Builder nesnesinin kendisini) döndürdüğünde, çağrılar zincirlenebilir ve bu akıcı bir API (fluent API) oluşturur. Sonuç, Python ve Scala'daki adlandırılmış opsiyonel parametrelere (named optional parameters) benzer bir kullanım deneyimi sunar. When Builder setter methods return this (the Builder itself), calls can be chained, creating a fluent API. The result resembles the named optional parameters found in Python and Scala.
✗ Kötü (zincirleme yok) 
// Kötü: Her adım ayrı bir satır, builder tekrar tekrar yazılıyor
QueryBuilder qb = new QueryBuilder();
qb.table("users");
qb.where("age > 18");
qb.orderBy("name");
qb.limit(10);
Query q = qb.build();
Setter metotlar void dönüyor. Builder değişkeni her satırda tekrar yazılmak zorunda. Setter methods return void. Builder variable must be repeated on every line.
✓ İyi (akıcı API) 
// İyi: return this ile zincir oluşturuluyor
public QueryBuilder where(String condition) {
    this.condition = condition;
    return this; // Builder'ın kendisini döndür
}

// Kullanım: Tek satırda okunabilir zincirleme
Query q = new QueryBuilder()
    .table("users")
    .where("age > 18")
    .orderBy("name")
    .limit(10)
    .build();
Her metot Builder'ı döndürüyor. Kod sanki Türkçe bir cümle gibi soldan sağa akıyor. Every method returns the Builder. The code flows left-to-right like a natural sentence.
💡 İpucu: Java'da Stream API, StringBuilder ve JPA Criteria API gibi birçok yerleşik API, akıcı arayüz tasarımını kullanır. Kendi Builder'larınızda da bu deseni uygulayın. 💡 Tip: Java's built-in APIs like Stream, StringBuilder, and JPA Criteria use fluent design. Apply this same pattern in your own Builders.
