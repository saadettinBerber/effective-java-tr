Chapter 4 — Item 17: Değişmezlik — Complex Sınıfı
↩ Önceki sayfadan devam — Madde 17: Complex sınıfı ve fonksiyonel yaklaşım

İşte değişmez bir karmaşık sayı (complex number) sınıfı örneği:

Here's an example immutable complex number class:

public final class Complex { private final double re; private final double im; public Complex(double re, double im) { this.re = re; this.im = im; } public double realPart() { return re; } public double imaginaryPart() { return im; } public Complex plus(Complex c) { return new Complex(re + c.re, im + c.im); } public Complex minus(Complex c) { return new Complex(re - c.re, im - c.im); } public Complex times(Complex c) { return new Complex(re * c.re - im * c.im, re * c.im + im * c.re); } // equals, hashCode, toString çıkarıldı... }

Aritmetik işlemlerin this örneğini değiştirmek yerine yeni bir Complex örneği oluşturduğuna dikkat edin. Bu kalıp fonksiyonel yaklaşım (functional approach) olarak bilinir — metotlar, işlenen (operand) nesneyi değiştirmeden, bir fonksiyonu uygulamanın sonucunu döndürür. Yöntem adlarının fiiller (add) yerine edatlar (plus) olduğuna dikkat edin — bu, metotların nesnenin durumunu değiştirmediği gerçeğini vurgular.

Değişmez nesnelerin avantajları:

1. Basittirler. Bir değişmez nesne tam olarak bir durumda bulunabilir: oluşturulduğu durumda. Tüm yapıcıların sınıf değişmezlerini oluşturduğundan emin olursanız, bu değişmezlerin her zaman geçerli kaldığı garantidir.

2. Doğası gereği iş parçacığı güvenlidirler (thread-safe). Senkronizasyon gerektirmezler. Birden çok iş parçacığı tarafından eşzamanlı olarak erişildiğinde bozulamazlar. Bu, iş parçacığı güvenliğini başarmanın açık ara en kolay yoludur. Değişmez nesneler özgürce paylaşılabilir.

3. Savunmacı kopyalarına gerek yoktur. Bir kopya orijinalden sonsuza kadar farksız olacaksa neden kopyalasın?

The arithmetic methods return new instances — the functional approach. Immutable advantages: 1) Simple — single state, 2) Thread-safe — no synchronization needed, 3) No defensive copies needed.

Fonksiyonel Yaklaşım

Fonksiyonel yaklaşımda (functional approach) metotlar mevcut nesneyi değiştirmez, bunun yerine sonucu yeni bir nesne olarak döndürür. Bu kalıp:

• İş parçacığı güvenliğini garanti eder
• Nesnenin tutarlılığını korur
• Yan etkisi (side effect) olmayan kodlar üretir

İsimlendirme: add (fiil, değiştirir) yerine plus (edat, değiştirmez) kullanılır.

Functional approach: methods return new objects instead of modifying this. Use prepositions (plus) not verbs (add) to signal immutability.
