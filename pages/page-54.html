Chapter 3 — Item 13: clone — Derin Kopya
↩ Önceki sayfadan devam — Madde 13: HashTable derin kopya çözümleri

Sorunu çözmek için, her kovayı oluşturan bağlantılı listeyi kopyalamanız gerekir. İşte yaygın bir yaklaşım — özyinelemeli derin kopya:

To fix this, copy the linked list in each bucket. Here's the recursive deep copy approach:

// Özyinelemeli derin kopya Entry deepCopy() { return new Entry(key, value, next == null ? null : next.deepCopy()); } @Override public HashTable clone() { try { HashTable result = (HashTable) super.clone(); result.buckets = new Entry[buckets.length]; for (int i = 0; i < buckets.length; i++) if (buckets[i] != null) result.buckets[i] = buckets[i].deepCopy(); return result; } catch (CloneNotSupportedException e) { throw new AssertionError(); } }

Bu teknik sevimli olsa da ve kovalar çok uzun olmadığı sürece iyi çalışsa da, bağlantılı bir listeyi klonlamak için iyi bir yol değildir — çünkü listedeki her eleman için bir yığın çerçevesi (stack frame) tüketir. Liste uzunsa, bu kolayca yığın taşmasına (stack overflow) neden olabilir. Bunu önlemek için deepCopy'deki özyinelemeyi iterasyon ile değiştirebilirsiniz:

This works but consumes one stack frame per element — can cause stack overflow for long lists. Replace recursion with iteration:

// İteratif derin kopya — yığın taşması riski yok Entry deepCopy() { Entry result = new Entry(key, value, next); for (Entry p = result; p.next != null; p = p.next) p.next = new Entry(p.next.key, p.next.value, p.next.next); return result; }

Karmaşık değişebilir nesneleri klonlamak için son bir yaklaşım da, super.clone() çağırdıktan sonra sonuç nesnesindeki tüm alanları başlangıç durumuna ayarlamak, ardından orijinal nesnenin durumunu yeniden oluşturmak için üst düzey metotları çağırmaktır. HashTable örneğinde, buckets alanı yeni boş bir kova dizisi olarak başlatılır ve klonlanan hash tablosundaki her anahtar-değer eşlemesi için put(key, value) çağrılır. Bu yaklaşım basit ve zarif bir clone metodu verir; ancak klonun iç yapısını doğrudan işleyen bir yaklaşım kadar hızlı çalışmaz.

Bir yapıcı (constructor) gibi, clone metodu, yapım aşamasındaki klon üzerinde asla ezilecek (overridable) bir metot çağırmamalıdır (Madde 19). Eğer clone bir alt sınıfta ezilmiş bir metodu çağırırsa, bu metot alt sınıf klondaki durumunu düzeltme şansı bulamadan çalışacaktır — bu da muhtemelen hem klonun hem de orijinalin bozulmasına yol açacaktır.

Object'in clone metodu CloneNotSupportedException fırlattığını bildirse de, ezen metotların bunu bildirmesi gerekmez. Genel (public) clone metotları throws cümlesini çıkarmalıdır; çünkü istisna fırlatmayan metotları kullanmak daha kolaydır (Madde 71).

An alternative: call super.clone, reset all fields, then use high-level methods like put(key, value) to regenerate state. Simple but slower.

Like a constructor, clone should never invoke overridable methods (Item 19). Public clone methods should omit throws CloneNotSupportedException.

🔍 Kavramlar: 🔍 Concepts:

Derin Kopya Yaklaşımları

1. Özyinelemeli deepCopy: Basit ve zarif, ancak uzun listeler için StackOverflowError riski taşır.

2. İteratif deepCopy: Yığın taşması riski olmadan bağlantılı listeyi kopyalar — tercih edilen yöntem.

3. Üst düzey yeniden oluşturma: super.clone() → alanları sıfırla → put() ile doldurun. Basit ama yavaş ve Cloneable mimarisinin ruhuyla çelişir.

1. Recursive deepCopy: Simple but stack overflow risk.
2. Iterative deepCopy: Preferred, no overflow.
3. High-level regeneration: Simple but slow.
