↩ Önceki sayfadan devam — Madde 16: Erişimci metotlar

Bu tür veriye doğrudan erişim sağlayan sınıflar kapsüllemenin faydalarını sunmaz (Madde 15). Temsili API'yi değiştirmeden değiştiremezsiniz, değişmezleri uygulayamazsınız ve bir alana erişildiğinde yardımcı eylem alamazsınız. Katı nesne yönelimli programcılar, bu tür sınıfların her zaman özel alanlar ve erişimci metotlar (getters) ile değiştirilmesi gerektiğini savunurlar:

These classes don't offer encapsulation. Replace with private fields and accessor methods:

// Erişimci metotlarla veri kapsülleme class Point { private double x; private double y; public Point(double x, double y) { this.x = x; this.y = y; } public double getX() { return x; } public double getY() { return y; } public void setX(double x) { this.x = x; } public void setY(double y) { this.y = y; } }

Genel sınıflar söz konusu olduğunda katılaşatılar kesinlikle haklıdır: Bir sınıf paketinin dışından erişilebiliyorsa, sınıfın iç temsilini değiştirme esnekliğini korumak için erişimci metotlar sağlayın.

Ancak, bir sınıf paket-özel (package-private) veya özel bir iç sınıf (private nested class) ise, veri alanlarını açığa çıkarmakta doğal olarak yanlış bir şey yoktur — soyutlamayı yeterince tanımlıyorlarsa. Bu, sınıf tanımında ve istemci kodunda daha az görsel karmaşa üretir.

Madde 16 — Özet: Genel sınıflar asla değişebilir alanları açığa çıkarmamalı. Değişmez alanları açığa çıkarmak daha az zararlıdır ama yine de sorgulanabilir. Ancak, paket-özel veya özel iç sınıfların alanları açığa çıkarması bazen (değişebilir veya değişmez) arzu edilir.

For public classes, always use accessors. For package-private or private nested classes, exposing fields is acceptable.

Item 16 — Summary: Public classes should never expose mutable fields. Package-private/private nested classes can.

Madde 17: Değişmezliği En Aza İndirin

Item 17: Minimize mutability

Değişmez (immutable) bir sınıf, örnekleri değiştirilemeyen bir sınıftır. Her örnekte bulunan tüm bilgiler oluşturma zamanında sabitlenir ve nesnenin ömrü boyunca asla değişmez. Java platformu kütüphaneleri String, BigInteger, BigDecimal ve sarmalayıcı sınıflar gibi birçok değişmez sınıf içerir. Bir sınıfı değişmez yapmak için şu beş kurala uyun:

1. Nesnenin durumunu değiştiren hiçbir metot sağlamayın (setter/mutator yok).
2. Sınıfın genişletilemeyeceğinden emin olun (final sınıf veya özel yapıcılar).
3. Tüm alanları final yapın.
4. Tüm alanları private yapın.
5. Değişebilir bileşenlere özel erişim sağlayın (savunmacı kopyalama).

An immutable class has instances that cannot be modified. Five rules: 1) No mutators, 2) Can't be extended, 3) All fields final, 4) All fields private, 5) Exclusive access to mutable components.

🔍 Kavramlar: 🔍 Concepts:

Değişmezliğin 5 Kuralı

1. Mutator yok: Setter metotları veya durumu değiştiren hiçbir metot olmaz.
2. Genişletilemez: final class veya yapıcıları private yaparak.
3. Alanlar final: Tüm alanlar final — doğru yapım sinyali verir.
4. Alanlar private: İstemciler alanlara doğrudan erişemez.
5. Savunmacı kopyalama: Değişebilir iç bileşenlere dış kaynaklı referans bulunmaz.

1) No mutators, 2) Class can't be extended, 3) All fields final, 4) All fields private, 5) Defensive copying for mutable components.
