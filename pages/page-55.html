Chapter 3 — Item 13: clone — Kalıtım & Alternatifler
↩ Önceki sayfadan devam — Madde 13: Kalıtım için clone tasarımı ve alternatifler

Kalıtım için tasarlanmış bir sınıf (Madde 19), Cloneable uygulamamalıdır. Object'in davranışını taklit ederek düzgün çalışan korumalı (protected) bir clone metodu uygulayabilirsiniz. Ya da clone'u aşağıdaki gibi dejenere bir formda uygulayarak alt sınıfların onu uygulamasını önleyebilirsiniz:

A class designed for inheritance (Item 19) should not implement Cloneable. You can either implement a protected clone mimicking Object, or prevent subclasses from implementing it:

// Alt sınıfların Cloneable uygulamasını önleyen clone metodu @Override protected final Object clone() throws CloneNotSupportedException { throw new CloneNotSupportedException(); }

İş parçacığı güvenli (thread-safe) bir sınıf yazıyorsanız Cloneable'ı uygulamanız gerekiyorsa, clone metodunuzun düzgün senkronize edildiğinden emin olun — tıpkı diğer metotlar gibi (Madde 78). Object'in clone metodu senkronize değildir; bu nedenle super.clone() iyi çalışsa bile, clone metodunu senkronize etmeniz gerekebilir.

Özetlemek gerekirse, Cloneable'ı uygulayan tüm sınıflar, dönüş türü sınıfın kendisi olan bir genel (public) clone metodu sağlamalıdır. Bu metot önce super.clone(code> çağırmalı, ardından düzeltilmesi gereken tüm alanları düzeltmelidir — yani nesnenin iç "derin yapısını" (deep structure) oluşturan tüm değişebilir nesneleri kopyalamak ve bu kopyalara yapılan referansları düzeltmek.

Tüm bu karmaşıklık gerçekten gerekli midir? Nadiren. Bir sınıf zaten Cloneable'ı uyguluyorsa, düzgün çalışan bir clone metodu sağlamanın başka yolu yoktur. Aksi halde, nesneleri kopyalamak için alternatif yollar sağlamanız veya sadece kopyalama yeteneği sağlamamanız daha iyidir. Değişmez (immutable) sınıflar asla klonlamayı desteklememelidir — çünkü kopyalar orijinallerinden ayırt edilemez olacağından sadece boşuna çaba olur.

Nesne kopyalamanın daha iyi bir yaklaşımı, bir kopya yapıcı (copy constructor) veya kopya fabrikası (copy factory) sağlamaktır:

Thread-safe classes implementing Cloneable must synchronize clone. In summary, all classes implementing Cloneable should provide a public clone that calls super.clone and fixes all mutable fields. But is this complexity necessary? Rarely. Better to provide copy constructors or copy factories, or not support copying at all. Immutable classes should never support cloning.

// Kopya yapıcı (Copy constructor) public Yum(Yum yum) { ... } // Kopya fabrikası (Copy factory) public static Yum newInstance(Yum yum) { ... }

Kopya yapıcı / kopya fabrika yaklaşımının Cloneable/clone'a göre pek çok avantajı vardır:

• Riskli, dil-dışı nesne oluşturma mekanizmasına dayanmazlar
• Yetersiz belgelenmiş sözleşmelere zorunlu bağlılık gerektirmezler
• final alanların doğru kullanımıyla çelişmezler
• Gereksiz kontrollü istisna fırlatmazlar
• Tür dönüştürme (cast) gerektirmezler
• Bir arayüz türü kabul edebilirler — dönüştürme yapıcıları (conversion constructors) olarak da bilinirler

Örneğin, HashSet nesnesinin TreeSet kopyasını oluşturmak: new TreeSet<>(hashSet). clone ile bunu yapamazsınız!

Copy constructors/factories don't rely on extralinguistic mechanisms, don't conflict with final fields, don't throw checked exceptions, don't require casts, and can accept interface types (conversion constructors). Example: new TreeSet<>(hashSet).

🔍 Kavramlar: 🔍 Concepts:

Kopya Yapıcı vs clone

Klon: Dil-dışı, kırılgan, final ile uyumsuz, CloneNotSupportedException fırlatır, tür dönüştürme gerektirir.

Kopya yapıcı: Normal Java yapıcısıdır, güvenlidir, final alanlarla çalışır, istisna gerektirmez, arayüz parametresi kabul edebilir.

Örnek: new TreeSet<>(hashSet) — HashSet'ten TreeSet'e dönüştürme. clone ile bu imkansızdır.

Clone: Extralinguistic, fragile, incompatible with final.
Copy constructor: Normal Java constructor, safe, works with final, can accept interface types like new TreeSet<>(hashSet).

💡 Kural: Yeni sınıflar için Cloneable yerine kopya yapıcı veya kopya fabrikası kullanın. Yalnızca diziler için clone() kullanmak mantıklıdır.
