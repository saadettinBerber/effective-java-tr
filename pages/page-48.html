Chapter 3 — Item 11: hashCode — PhoneNumber & Objects.hash()
↩ Önceki sayfadan devam — Madde 11: PhoneNumber hashCode uygulaması

Önceki tarifi PhoneNumber sınıfına uygulayalım:

Let's apply the previous recipe to the PhoneNumber class:

// Tipik hashCode metodu @Override public int hashCode() { int result = Short.hashCode(areaCode); result = 31 * result + Short.hashCode(prefix); result = 31 * result + Short.hashCode(lineNum); return result; }

Bu metot basit, makul ölçüde hızlıdır ve eşit olmayan telefon numaralarını farklı hash kovalarına makul ölçüde dağıtır. Java platform kütüphanelerindeki değer türlerindeki hash fonksiyonlarıyla karşılaştırılabilir kalitededir ve çoğu kullanım için yeterlidir.

Objects sınıfı, rastgele sayıda nesne alan ve onlar için bir hash kodu döndüren hash adlı statik bir metoda sahiptir. Bu metot, tarife göre yazılanlarla kalitesi karşılaştırılabilir tek satırlık hashCode metotları yazmanıza olanak tanır. Ne yazık ki, değişken sayıda argüman geçirmek için dizi oluşturmayı, ayrıca ilkel türlerden herhangi biri varsa sarmalama (boxing) ve çözme (unboxing) gerektirdiğinden daha yavaş çalışırlar. Bu tarz hash fonksiyonu yalnızca performansın kritik olmadığı durumlarda önerilir:

This method is simple, reasonably fast, and does a reasonable job of dispersing unequal phone numbers into different hash buckets. Comparable in quality to Java platform libraries' value types.

Objects class has a static hash method that takes arbitrary number of objects. Lets you write one-line hashCode methods, but runs slower due to array creation and boxing/unboxing. Recommended only when performance is not critical:

// Tek satırlık hashCode — orta düzeyde performans @Override public int hashCode() { return Objects.hash(lineNum, prefix, areaCode); }

Bir sınıf değişmez (immutable) ise ve hash kodunu hesaplama maliyeti önemliyse, hash kodunu her istendiğinde yeniden hesaplamak yerine nesnenin içinde önbelleğe almayı (caching) düşünebilirsiniz. Hash kodu istendiğinde tembel başlatma (lazy initialization) ile hesaplayabilirsiniz:

If a class is immutable and hash code computation is significant, consider caching the hash code. You can use lazy initialization:

// Tembel başlatmalı önbellekli hashCode metodu private int hashCode; // Otomatik olarak 0'a başlatılır @Override public int hashCode() { int result = hashCode; if (result == 0) { result = Short.hashCode(areaCode); result = 31 * result + Short.hashCode(prefix); result = 31 * result + Short.hashCode(lineNum); hashCode = result; } return result; }

Performansı iyileştirmek amacıyla önemli alanları hash kodu hesaplamasından çıkarmaya kalkışmayın. Ortaya çıkan hash fonksiyonu daha hızlı çalışabilir; ancak düşük kalitesi hash tablolarının performansını kullanılamaz hale getirecek düzeyde düşürebilir. Java 2'den önce String hash fonksiyonu en fazla 16 karakter kullanırdı — bu kararın URL gibi hiyerarşik isim koleksiyonlarında tam olarak patolojik davranışa yol açtığı görüldü.

hashCode tarafından döndürülen değer için ayrıntılı bir belirtim (specification) sağlamayın — istemciler ona makul ölçüde bağımlı olamasın; bu size onu değiştirme esnekliği verir. String ve Integer gibi birçok Java sınıfı hashCode değerini belirli bir formül olarak belirtir — bu iyi bir fikir değildi, ama birlikte yaşamak zorunda olduğumuz bir hataydı.

Don't exclude significant fields to improve performance. Pre-Java 2 String hash used only 16 characters — caused pathological behavior with URLs.

Don't specify the exact value returned by hashCode so clients can't depend on it. String and Integer specifying their formulas was a mistake.

🔍 Kavramlar: 🔍 Concepts:

Objects.hash()

Objects.hash(Object... values) Java 7'den beri mevcuttur. Kısa ve temiz bir hashCode uygulaması sağlar; ancak iki dezavantajı vardır:

1. Dizi oluşturma: Varargs parametreleri için her çağrıda bir Object[] dizisi oluşturulur.

2. Autoboxing: İlkel tür alanları otomatik olarak sarmalanır (int → Integer), ek maliyet yaratır.

Objects.hash() is available since Java 7. Clean but has overhead: array creation for varargs and autoboxing for primitives.

💡 Performans kritikse elle 31 * result + c tarifini uygulayın. Kritik değilse Objects.hash() kullanmak sorun değildir.

Tembel hashCode Önbelleği

Değişmez sınıflarda hash kodu yalnızca bir kez hesaplanıp bir alana kaydedilebilir. İlk istekte hesaplanır (tembel başlatma), sonraki çağrılarda önbellekteki değer döndürülür.

Dikkat: Başlangıç değeri (0), yaygın olarak oluşturulan bir örneğin hash kodu olmamalıdır; aksi halde tembel başlatma tetiklenmez. Ayrıca, tembel başlatılmış alan varken sınıfın iş parçacığı güvenli (thread-safe) kalmasına dikkat edilmelidir (Madde 83).

In immutable classes, the hash code can be computed once and cached. Computed lazily on first request, then returns cached value. Initial value (0) shouldn't be the hash code of a commonly created instance.
