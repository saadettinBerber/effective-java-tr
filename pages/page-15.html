Item 2: Consider a builder when faced with many constructor parameters Madde 2: Çok Sayıda Parametreyle Karşılaşınca Builder'ı Düşünün
↩ Önceki sayfadan devam: Builder kalıbının sınıf hiyerarşilerine uygunluğu anlatılıyordu. ↩ Continued from previous page: How the Builder pattern suits class hierarchies was being discussed.
Builder kalıbı — sınıf hiyerarşisi (Pizza soyut sınıfı)
Builder pattern for class hierarchies (abstract Pizza class)
// Builder kalıbı — sınıf hiyerarşileri için
public abstract class Pizza {
    public enum Topping { HAM, MUSHROOM, ONION, PEPPER, SAUSAGE }
    final Set<Topping> toppings;

    abstract static class Builder<T extends Builder<T>> {
        EnumSet<Topping> toppings = EnumSet.noneOf(Topping.class);

        public T addTopping(Topping topping) {
            toppings.add(Objects.requireNonNull(topping));
            return self();
        }

        abstract Pizza build();

        // Alt sınıflar bu metodu "this" döndürecek şekilde override etmeli
        protected abstract T self();
    }

    Pizza(Builder<?> builder) {
        toppings = builder.toppings.clone(); // Madde 50
    }
}
Not: Pizza.Builder, özyinelemeli tip parametresine (recursive type parameter) sahip bir jenerik tiptir (Madde 30). abstract T self() metodu sayesinde metot zincirleme, alt sınıflarda cast gerekmeden doğru şekilde çalışır. Java'da "kendi tipinin" bulunmamasına karşı bu geçici çözüm benzetilmiş kendi tipi (simulated self-type) deyimi olarak bilinir. Note: Pizza.Builder is a generic type with a recursive type parameter (Item 30). This, along with the abstract self method, allows method chaining to work properly in subclasses without the need for casts. This workaround for Java's lack of a self type is known as the simulated self-type idiom.

İşte Pizza'nın iki somut alt sınıfı: biri standart New York usulü pizzayı, diğeri calzone'u temsil eder. Birincisi zorunlu bir boyut (size) parametresi alırken, ikincisi sosin içeride mi dışarıda mı olacağını belirlemeye olanak tanır:

Here are two concrete subclasses of Pizza, one of which represents a standard New-York-style pizza, the other a calzone. The former has a required size parameter, while the latter lets you specify whether sauce should be inside or out:

NyPizza — somut alt sınıf
NyPizza — concrete subclass
public class NyPizza extends Pizza {
    public enum Size { SMALL, MEDIUM, LARGE }
    private final Size size;

    public static class Builder extends Pizza.Builder<Builder> {
        private final Size size;

        public Builder(Size size) {
            this.size = Objects.requireNonNull(size);
        }

        @Override public NyPizza build() {
            return new NyPizza(this);
        }

        @Override protected Builder self() { return this; }
    }

    private NyPizza(Builder builder) {
        super(builder);
        size = builder.size;
    }
}

Özyinelemeli Tip ParametresiRecursive Type Parameter
Builder<T extends Builder<T>> kalıbıThe Builder<T extends Builder<T>> pattern
Özyinelemeli tip parametresi T extends Builder<T>, bir Builder'ın kendi tipini döndürmesini sağlar. Bu sayede alt sınıf builder'larında zincirleme metotlar doğru tipi döndürür ve cast gerekmez. The recursive type parameter T extends Builder<T> lets a Builder return its own type. Chained methods in subclass builders thus return the correct type without casting.
✗ Kötü (cast gerekiyor) 
// Cast olmadan alt sınıf metodu çalışmıyor
(AnimalBuilder) new DogBuilder()
    .breed("Labrador")   // Object döner — cast şart
    .color("black")
    .build();
Üst sınıf Builder döndürdüğünden alt sınıf metotlarına erişmek için cast gerekiyor.Since the superclass returns Builder, you need a cast to access subclass methods.
✓ İyi (özyinelemeli tip parametresi ile) 
// T extends Builder<T> ile cast gereksiz
Dog dog = new DogBuilder()
    .breed("Labrador")   // DogBuilder döner
    .color("black")     // DogBuilder döner
    .build();            // Dog döner
Özyinelemeli tip sayesinde her metot doğru alt tipi döndürüyor, cast yok.Thanks to the recursive type, each method returns the correct subtype, no cast needed.
💡 İpucu: Bu kalıp Jenerikler bölümünde Madde 30'da ayrıntılı anlatılmaktadır.💡 Tip: This pattern is detailed in Item 30 of the Generics chapter.
Benzetilmiş Kendi Tipi (Simulated Self-Type)Simulated Self-Type Idiom
abstract T self() metodu ile kendi tipin döndürülmesiReturning own type via abstract T self() method
Swift ve Kotlin gibi dillerde Self tipi vardır; Java'da yoktur. abstract T self() metodu bu eksikliği giderir: her alt sınıf self()'i return this; olarak override eder, böylece üst sınıfın zincirleme metotları alt sınıfı döndürür. Languages like Swift and Kotlin have a Self type; Java does not. The abstract T self() method fills this gap: each subclass overrides self() to return this, so the parent's chained methods return the subclass type. 
// Üst sınıfta:
protected abstract T self();

// Alt sınıfta:
@Override
protected ConcreteBuilder self() { return this; }
Her alt sınıf self()'i override ederek kendini döndürüyor. Üst sınıfın addTopping gibi metotları bu sayede doğru alt tipi zincirleyebiliyor.Each subclass overrides self() to return itself. The parent's methods like addTopping can thus chain the correct subtype.
Kovaryant Dönüş Tipi (Covariant Return Typing)Covariant Return Typing
Alt sınıf metodu üst sınıfın dönüş tipiyle aynı veya daha özgül bir tip döndürürSubclass method returns the same or a more specific return type than the superclass
NyPizza.Builder.build() NyPizza döndürür, Pizza değil. Bu kovaryant dönüş tipidir: istemci NyPizza beklerken cast yapmadan direkt kullanabilir. NyPizza.Builder.build() returns NyPizza, not Pizza. This is covariant return typing: the client can use it directly as NyPizza without casting. 
// Kovaryant dönüş tipi sayesinde istemci cast yapmıyor
NyPizza pizza = new NyPizza.Builder(NyPizza.Size.LARGE)
    .addTopping(Pizza.Topping.SAUSAGE)
    .build(); // NyPizza döner, Pizza değil
Cast olmadan NyPizza türünde bir değişkene atanabiliyor.Can be assigned to an NyPizza variable without any cast.
💡 İpucu: Kovaryant dönüş tipi Java 5'ten beri desteklenmektedir. Bu özellik, builder hiyerarşilerini istemci açısından temiz tutmanın anahtarıdır.💡 Tip: Covariant return typing has been supported since Java 5. It's the key to keeping builder hierarchies clean for clients.
