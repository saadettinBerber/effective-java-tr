↩ Önceki sayfadan devam — Madde 18: ForwardingSet sarmalama çözümü

İşte bileşim ve yönlendirme (forwarding) ile doğru uygulama:

Here's the correct implementation using composition and forwarding:

// Sarmalayıcı (Wrapper) sınıf — kalıtım yerine bileşim public class InstrumentedSet<E> extends ForwardingSet<E> { private int addCount = 0; public InstrumentedSet(Set<E> s) { super(s); } @Override public boolean add(E e) { addCount++; return super.add(e); } @Override public boolean addAll(Collection<? extends E> c) { addCount += c.size(); return super.addAll(c); } public int getAddCount() { return addCount; } } // Yeniden kullanılabilir yönlendirme sınıfı public class ForwardingSet<E> implements Set<E> { private final Set<E> s; public ForwardingSet(Set<E> s) { this.s = s; } public boolean add(E e) { return s.add(e); } public boolean addAll(Collection<? extends E> c) { return s.addAll(c); } // ... diğer Set metotlarını s'ye delege eder }

Bu tasarımda addAll, ForwardingSet.addAll()'ı çağırır — bu da sarılmış Set'in addAll'ını çağırır. Bizim add'imiz bu zincirde yer almaz! Kendi kendini kullanma sorunu ortadan kalkmıştır.

Kalıtımı yalnızca "A bir B'dir" (is-a) ilişkisi gerçekten geçerli olduğunda kullanın. Kendinize sorun: Her B gerçekten bir A mıdır? Yanıt hayırsa bileşim kullanın.

Madde 18 — Özet: Kalıtım güçlüdür ama kapsüllemeyi kırdığı için sorunludur. Yalnızca alt sınıf ile üst sınıf arasında gerçek bir "is-a" ilişkisi varsa kullanın. Aksi halde bileşim ve yönlendirme kullanın. Sarmalayıcı sınıflar yalnızca daha sağlam değil, aynı zamanda daha güçlüdür.

The forwarding breaks the self-use chain. Use inheritance only for true "is-a" relationships.

Item 18 — Summary: Inheritance violates encapsulation. Use composition and forwarding unless there's a true "is-a" relationship.

Madde 19: Kalıtım İçin Tasarlayın ve Belgeleyin ya da Yasaklayın

Item 19: Design and document for inheritance or else prohibit it

Kalıtım için tasarlanmış bir sınıfın, ezilecek her metodun kendi kendini kullanımını belgelemesi gerekir — @implSpec etiketi kullanarak. Üst sınıf, protected metotlar veya alanlar biçiminde dikkatle seçilmiş kancalar (hooks) sağlayarak alt sınıfların iç işleyişine kontrollü erişim vermeli. Kalıtım için tasarlanmış bir sınıfı piyasaya sürmeden önce, alt sınıflar yazarak test etmelisiniz — genellikle 3 alt sınıf yeterlidir.

Kalıtım için tasarlanmamış sınıfları kalıtıma kapatın: ya final yapın ya da tüm yapıcıları private veya paket-özel yapıp statik fabrika metotları sağlayın.

Classes designed for inheritance must document self-use of overridable methods (@implSpec), provide hooks via protected methods, and be tested with ~3 subclasses. Close classes not designed for inheritance — make final or use private constructors.
