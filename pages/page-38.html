...x.equals(y), yalnızca ve yalnızca (if and only if) y.equals(x) true döndürdüğünde true döndürmelidir.

• Geçişli (Transitive): Herhangi bir null olmayan referans değerleri x, y, z için, eğer x.equals(y) true döndürüyorsa ve y.equals(z) true döndürüyorsa, o zaman x.equals(z) de true döndürmelidir.

• Tutarlı (Consistent): Herhangi bir null olmayan referans değerleri x ve y için, equals karşılaştırmalarında kullanılan hiçbir bilgi değiştirilmediği sürece, x.equals(y)'nin birden fazla çağrılması sürekli olarak true veya sürekli olarak false döndürmelidir.

• Herhangi bir null olmayan referans değeri x için, x.equals(null) false döndürmelidir.

Matematiğe eğilimli (mathematically inclined) değilseniz, bu biraz korkutucu görünebilir; ama onu görmezden gelmeyin! İhlal ederseniz, programınızın düzensiz davrandığını (behaves erratically) veya çöktüğünü görebilirsiniz ve başarısızlığın kaynağını tespit etmek (pin down) çok zor olabilir. John Donne'u alıntılamak gerekirse, hiçbir sınıf bir ada değildir (no class is an island). Bir sınıfın örnekleri sık sık başka bir sınıfa aktarılır. Tüm koleksiyon sınıfları dahil olmak üzere birçok sınıf, kendilerine aktarılan nesnelerin equals sözleşmesine uymasına bağımlıdır.

Artık equals sözleşmesini ihlal etmenin tehlikelerinin farkında olduğunuza göre, sözleşmeyi detaylıca gözden geçirelim. İyi haber şu ki, görünüşün aksine, aslında o kadar karmaşık değildir. Bir kez anladığınızda, ona uymak zor değildir.

Peki bir denklik ilişkisi (equivalence relation) nedir? Kabaca söylemek gerekirse, bir eleman kümesini, elemanları birbirine eşit sayılan alt kümelere (subsets) bölen bir operatördür. Bu alt kümelere denklik sınıfları (equivalence classes) denir. Bir equals metodunun yararlı olması için, her denklik sınıfındaki tüm elemanlar kullanıcının bakış açısından birbirleriyle değiştirilebilir (interchangeable) olmalıdır. Şimdi beş gereksinimi sırasıyla inceleyelim:

Dönüşlülük (Reflexivity) — İlk gereksinim basitçe bir nesnenin kendisine eşit olması gerektiğini söyler. Bunu yanlışlıkla ihlal etmeyi hayal etmek zordur. İhlal edip sonra sınıfınızın bir örneğini bir koleksiyona eklerseniz, contains metodu yeni eklediğiniz örneğin koleksiyonda olmadığını söyleyebilir.

Simetri (Symmetry) — İkinci gereksinim, herhangi iki nesnenin eşit olup olmadıkları konusunda hemfikir olması gerektiğini söyler. İlk gereksinimin aksine, bunu yanlışlıkla ihlal etmeyi hayal etmek zor değildir. Örneğin, büyük/küçük harfe duyarsız (case-insensitive) bir string uygulayan şu sınıfı düşünün. String'in harfleri toString tarafından korunur ancak equals karşılaştırmalarında göz ardı edilir:

...x.equals(y) must return true if and only if y.equals(x) returns true.

• Transitive: For any non-null reference values x, y, z, if x.equals(y) returns true and y.equals(z) returns true, then x.equals(z) must return true.

• Consistent: For any non-null reference values x and y, multiple invocations of x.equals(y) must consistently return true or consistently return false, provided no information used in equals comparisons is modified.

• For any non-null reference value x, x.equals(null) must return false.

Unless you are mathematically inclined, this might look a bit scary, but do not ignore it! If you violate it, you may well find that your program behaves erratically or crashes, and it can be very difficult to pin down the source of the failure. To paraphrase John Donne, no class is an island. Instances of one class are frequently passed to another. Many classes, including all collections classes, depend on the objects passed to them obeying the equals contract.

Now that you are aware of the dangers of violating the equals contract, let's go over the contract in detail. The good news is that, appearances notwithstanding, it really isn't very complicated. Once you understand it, it's not hard to adhere to it.

So what is an equivalence relation? Loosely speaking, it's an operator that partitions a set of elements into subsets whose elements are deemed equal to one another. These subsets are known as equivalence classes. For an equals method to be useful, all of the elements in each equivalence class must be interchangeable from the perspective of the user. Now let's examine the five requirements in turn:

Reflexivity — The first requirement says merely that an object must be equal to itself. It's hard to imagine violating this one unintentionally. If you were to violate it and then add an instance of your class to a collection, the contains method might well say that the collection didn't contain the instance that you just added.

Symmetry — The second requirement says that any two objects must agree on whether they are equal. Unlike the first requirement, it's not hard to imagine violating this one unintentionally. 🔍 Kavramlar: 🔍 Concepts:

Dönüşlülük (Reflexivity)

Bir nesne kendisine eşit olmalıdır: x.equals(x) == true. Bu en temel gereksinimdir ve kasıtlı olarak ihlal edilmezse genellikle doğal olarak sağlanır. Ancak ihlal edilirse, koleksiyonların contains() metodu az önce eklediğiniz nesneyi bile bulamaz!

An object must equal itself: x.equals(x) == true. This is the most basic requirement and usually holds naturally unless intentionally violated. If violated, a collection's contains() won't find an object you just added!

Simetri (Symmetry)

x.equals(y) == true ise y.equals(x) == true olmalıdır. Simetri ihlali, genellikle kendi sınıfınızın equals'ında başka bir türle karşılaştırma yapmaya çalıştığınızda ortaya çıkar. Örneğin, CaseInsensitiveString sınıfı String ile eşitlik karşılaştırabileceğini düşünür, ancak String ise CaseInsensitiveString'i tanımaz.

If x.equals(y) == true then y.equals(x) == true. Symmetry violations typically arise when your class's equals tries to interoperate with a different type. E.g., CaseInsensitiveString thinks it equals a String, but String doesn't know about CaseInsensitiveString.

💡 Altın kural: equals metodu yalnızca kendi türünün nesneleriyle karşılaştırmalıdır. Farklı türlerle (cross-type) eşitlik sağlamaya çalışmak neredeyse her zaman simetrinin ihlaline yol açar.

Denklik Sınıfı (Equivalence Class)

Denklik sınıfı, bir denklik ilişkisi tarafından "eşit" sayılan elemanların oluşturduğu alt kümedir. Örneğin, Integer sınıfının equals metodu ile, new Integer(42) ve Integer.valueOf(42) aynı denklik sınıfına aittir çünkü aynı değeri temsil ederler.

Bir equals metodunun yararlı olabilmesi için, aynı denklik sınıfındaki tüm nesneler kullanıcı açısından birbirleriyle değiştirilebilir (interchangeable) olmalıdır.

An equivalence class is a subset of elements deemed "equal" by an equivalence relation. For example, with Integer's equals, new Integer(42) and Integer.valueOf(42) belong to the same equivalence class because they represent the same value.

For an equals method to be useful, all objects in the same equivalence class must be interchangeable from the user's perspective.
