Chapter 3 — Item 14: Comparable — compareTo Uygulaması
↩ Önceki sayfadan devam — Madde 14: compareTo sözleşmesi detayları ve uygulama

equals sözleşmesinde olduğu gibi, mevcut bir Comparable sınıfını bir değer bileşeniyle genişletmenin ve compareTo sözleşmesini korumanın bir yolu yoktur; ama bir geçici çözüm (workaround) vardır. İlişkisiz bir sınıf yazın, onu orijinal sınıfın bir örneğini tutacak bir alanla donatın ve orijinal örneği döndüren bir "görünüm (view)" metodu sağlayın. Bu, dış sınıfta istediğiniz compareTo metodunu uygulamanıza olanak tanır — bileşim (composition) yaklaşımı, tıpkı Madde 10'da equals için yapıldığı gibi.

Bir compareTo metodunda alanlar eşitlik değil, sıralama için karşılaştırılır. Comparable arayüzünü uygulayan nesne referansı alanlarını compareTo metodunu özyinelemeli olarak çağırarak karşılaştırın. Comparable uygulamayan alanlar veya standart dışı sıralama gerektiren alanlar için açık bir Comparator kullanın.

compareTo metotlarında karşılaştırma yaparken < ve > ilişkisel operatörlerini kullanmaktan kaçının. Bunun yerine, sarmalayıcı (boxed) ilkel sınıflardaki statik compare metotlarını veya Comparator arayüzündeki karşılaştırıcı oluşturma metotlarını (comparator construction methods) kullanın.

İşte birden fazla alanlı PhoneNumber için compareTo metodu:

As with equals, there's no way to extend a Comparable class with a value component and preserve the contract — use composition instead. Use static compare methods instead of < and > operators. Here's the multi-field PhoneNumber compareTo:

// İlkel alanları olan çoklu-alan compareTo public int compareTo(PhoneNumber pn) { int result = Short.compare(areaCode, pn.areaCode); if (result == 0) { result = Short.compare(prefix, pn.prefix); if (result == 0) result = Short.compare(lineNum, pn.lineNum); } return result; }

Java 8'de Comparator arayüzü, karşılaştırıcı oluşturma metotları (comparator construction methods) ile donatıldı; bu metotlar akıcı (fluent) karşılaştırıcı oluşturulmasına olanak tanır. Pek çok programcı bu yaklaşımın kısalığını tercih eder; ancak makinemde PhoneNumber dizileri sıralama yaklaşık %10 daha yavaştır. İşte bu yaklaşımla compareTo:

In Java 8, Comparator gained comparator construction methods for fluent comparator creation. About 10% slower but much more concise:

// Comparator construction methods kullanarak private static final Comparator<PhoneNumber> COMPARATOR = comparingInt((PhoneNumber pn) -> pn.areaCode) .thenComparingInt(pn -> pn.prefix) .thenComparingInt(pn -> pn.lineNum); public int compareTo(PhoneNumber pn) { return COMPARATOR.compare(this, pn); }

Bu uygulama, sınıf başlatma zamanında iki karşılaştırıcı oluşturma metodu kullanarak bir karşılaştırıcı oluşturur. comparingInt, nesne referansından int türünde bir anahtara eşleme yapan bir anahtar çıkarıcı fonksiyon (key extractor) alır. thenComparingInt ise beraberlikleri kırmak için ikincil ve üçüncül anahtarlar ekler.

İlk lambda'da tür parametresini (PhoneNumber pn) açıkça belirtmek zorunda kaldığımıza dikkat edin — çünkü Java'nın tür çıkarımı bu durumda türü kendi başına belirleyecek kadar güçlü değildir.

comparingInt takes a key extractor function. thenComparingInt adds secondary/tertiary keys. Note that the first lambda needs explicit type parameter because Java's type inference can't figure it out.

Comparator Construction Methods

Java 8'den beri Comparator arayüzü akıcı API sağlar:

• comparingInt/Long/Double — ilkel anahtar çıkarıcıya göre birincil sıralama
• thenComparingInt/Long/Double — beraberlikleri kırmak için ikincil anahtar
• comparing(keyExtractor) — nesne anahtarları için doğal sıralama
• thenComparing(keyExtractor, comparator) — özel karşılaştırıcıyla ikincil sıralama

Performans notu: ~%10 ek maliyet olabilir ama okunabilirlik kazancı çoğu durumda buna değer.

Java 8+ Comparator construction: comparingInt, thenComparingInt, comparing, thenComparing. ~10% performance cost but much more readable.
