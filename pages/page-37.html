Chapter 3 — Item 10: equals'ı Ezerken Genel Sözleşmeye Uyun / Obey the general contract when overriding equals
↩ Önceki sayfadan devam — Madde 10: equals'ı ezmemenin uygun olduğu koşullar

...Object'ten miras alınan equals uygulaması idealdir.

• Bir üst sınıf (superclass) zaten equals'ı ezmiştir ve üst sınıfın davranışı bu sınıf için uygundur. Örneğin, çoğu Set uygulaması equals uygulamasını AbstractSet'ten, List uygulamaları AbstractList'ten ve Map uygulamaları AbstractMap'ten miras alır.

• Sınıf özel (private) veya paket-özel (package-private) ise ve equals metodunun asla çağrılmayacağından eminseniz. Son derece riskten kaçınan biri (extremely risk-averse) iseniz, yanlışlıkla çağrılmadığından emin olmak için equals metodunu şöyle ezebilirsiniz:

...equals implementation inherited from Object is ideal.

• A superclass has already overridden equals, and the superclass behavior is appropriate for this class. For example, most Set implementations inherit their equals implementation from AbstractSet, List implementations from AbstractList, and Map implementations from AbstractMap.

• The class is private or package-private, and you are certain that its equals method will never be invoked. If you are extremely risk-averse, you can override the equals method to ensure that it isn't invoked accidentally:

@Override public boolean equals(Object o) { throw new AssertionError(); // Metot asla çağrılmaz }

Peki equals'ı ezmek ne zaman uygundur? Bir sınıfın, salt nesne kimliğinden (mere object identity) farklı bir mantıksal eşitlik (logical equality) kavramı olduğunda ve bir üst sınıf henüz equals'ı ezmediğinde. Bu genellikle değer sınıfları (value classes) için geçerlidir. Bir değer sınıfı, Integer veya String gibi basitçe bir değeri temsil eden bir sınıftır. Değer nesnelerine yapılan referansları equals metoduyla karşılaştıran bir programcı, bunların mantıksal olarak eşdeğer (logically equivalent) olup olmadığını öğrenmeyi bekler; aynı nesneye mi işaret ettiklerini değil. equals metodunu ezmek yalnızca programcı beklentilerini karşılamak için gerekli olmakla kalmaz, aynı zamanda örneklerin öngörülebilir, istenen bir davranışla harita anahtarları (map keys) veya küme elemanları (set elements) olarak hizmet etmesini sağlar.

equals metodunun ezilmesini gerektirmeyen bir değer sınıfı türü, her değerle en fazla bir nesnenin var olmasını garanti altına almak için örnek denetimi (instance control) (Madde 1) kullanan bir sınıftır. Enum türleri (Madde 34) bu kategoriye girer. Bu sınıflar için mantıksal eşitlik, nesne kimliğiyle aynıdır; bu nedenle Object'in equals metodu mantıksal bir equals metodu olarak işlev görür.

equals metodunu ezdiğinizde, onun genel sözleşmesine (general contract) uymalısınız. İşte Object spesifikasyonundan bu sözleşme:

equals metodu bir denklik ilişkisi (equivalence relation) uygular. Şu özelliklere sahiptir:

• Dönüşlü (Reflexive): Herhangi bir null olmayan referans değeri x için, x.equals(x) true döndürmelidir.

• Simetrik (Symmetric): Herhangi bir null olmayan referans değerleri x ve y için, x.equals(y)...

So when is it appropriate to override equals? It is when a class has a notion of logical equality that differs from mere object identity and a superclass has not already overridden equals. This is generally the case for value classes. A value class is simply a class that represents a value, such as Integer or String. A programmer who compares references to value objects using the equals method expects to find out whether they are logically equivalent, not whether they refer to the same object. Not only is overriding the equals method necessary to satisfy programmer expectations, it enables instances to serve as map keys or set elements with predictable, desirable behavior.

One kind of value class that does not require the equals method to be overridden is a class that uses instance control (Item 1) to ensure that at most one object exists with each value. Enum types (Item 34) fall into this category. For these classes, logical equality is the same as object identity, so Object's equals method functions as a logical equals method.

When you override the equals method, you must adhere to its general contract. Here is the contract, from the specification for Object:

The equals method implements an equivalence relation. It has these properties:

• Reflexive: For any non-null reference value x, x.equals(x) must return true.

• Symmetric: For any non-null reference values x and y, x.equals(y)...

Değer Sınıfı (Value Class)

Bir değer sınıfı, basitçe bir değeri temsil eden sınıftır: Integer, String, BigDecimal, LocalDate vb. Bu sınıfların örneklerini karşılaştırırken, bellekteki adreslerini (kimlik) değil, taşıdıkları değerleri (eşitlik) karşılaştırmak isteriz.

Değer sınıfları mutlaka equals ve hashCode'u ezmelidir. Aksi takdirde HashMap ve HashSet gibi koleksiyonlar doğru çalışmaz.

A value class simply represents a value: Integer, String, BigDecimal, LocalDate, etc. When comparing instances, we want to compare the values they hold (equality), not their memory addresses (identity).

Value classes must override equals and hashCode. Otherwise, collections like HashMap and HashSet won't work correctly.

Denklik İlişkisi (Equivalence Relation)

Matematiksel bir denklik ilişkisi üç özelliğe sahip olmalıdır:

1. Dönüşlü (Reflexive): Her eleman kendisine eşittir → x.equals(x) = true

2. Simetrik (Symmetric): A, B'ye eşitse → B de A'ya eşittir

3. Geçişli (Transitive): A = B ve B = C ise → A = C

Ek olarak tutarlı (consistent) olmalıdır: aynı girdiler her zaman aynı sonucu vermelidir. Ve x.equals(null) her zaman false döndürmelidir.

A mathematical equivalence relation must have three properties:

1. Reflexive: Every element equals itself → x.equals(x) = true

2. Symmetric: If A equals B → B equals A

3. Transitive: If A = B and B = C → A = C

Additionally must be consistent: same inputs always give same result. And x.equals(null) must always return false.

Örnek Denetimi (Instance Control)

Örnek denetimi, bir sınıftan en fazla bir örnek oluşturulmasını garanti eden bir tasarım kalıbıdır. Singleton (Madde 3) ve Enum (Madde 34) bunun örnekleridir. Eğer her değer için yalnızca bir nesne varsa, nesne kimliği (==) ve mantıksal eşitlik (equals) aynı şeyi ifade eder; dolayısıyla equals'ı ezmeye gerek yoktur.

Instance control guarantees that at most one instance of a class exists per value. Singletons (Item 3) and Enums (Item 34) are examples. When only one object exists per value, object identity (==) and logical equality (equals) mean the same thing — no need to override equals.
