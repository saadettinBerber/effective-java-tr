Chapter 3 — Item 13: clone — Stack & Dizi
↩ Önceki sayfadan devam — Madde 13: Stack clone çözümü ve dizi klonlama

clone metodu aslında bir yapıcı (constructor) işlevi görür; orijinal nesneye zarar vermediğinden ve klon üzerinde değişmezleri (invariants) düzgün bir şekilde oluşturduğundan emin olmalısınız. Stack'in clone metodunun düzgün çalışması için yığının iç yapısını kopyalaması gerekir. Bunu yapmanın en kolay yolu, elements dizisi üzerinde clone'u özyinelemeli (recursively) çağırmaktır:

The clone method functions as a constructor; you must ensure it does no harm to the original and properly establishes invariants. For Stack, the easiest way is to call clone recursively on the elements array:

// Değişebilir duruma referans içeren sınıf için clone metodu @Override public Stack clone() { try { Stack result = (Stack) super.clone(); result.elements = elements.clone(); return result; } catch (CloneNotSupportedException e) { throw new AssertionError(); } }

elements.clone()'un sonucunu Object[]'ye dönüştürmemize gerek olmadığını unutmayın. Bir dizi üzerinde clone çağrmak, çalışma zamanı ve derleme zamanı türleri klonlanan diziyle aynı olan bir dizi döndürür. Bu, bir diziyi çoğaltmak için tercih edilen deyimdir (idiom). Aslında, diziler clone mekanizmasının tek zorlayıcı kullanım alanıdır.

elements alanı final olsaydı önceki çözümün çalışmayacağını da unutmayın; çünkü clone, alana yeni bir değer atamaktan yasaklanırdı. Bu temel bir sorundur: serileştirme (serialization) gibi, Cloneable mimarisi, değişebilir nesnelere atıfta bulunan final alanların normal kullanımıyla uyumsuzdur.

Yalnızca clone'u özyinelemeli olarak çağırmak her zaman yeterli değildir. İç yapıları bir kova (bucket) dizisinden oluşan bir hash tablosu düşünün; her kova, anahtar-değer çiftlerinin bağlantılı listesindeki ilk girişe referans verir:

Array clone returns an array of identical runtime and compile-time types — the preferred idiom for duplicating arrays. Arrays are the sole compelling use of the clone facility.

If elements were final, clone couldn't assign a new value. Cloneable is incompatible with final fields referring to mutable objects.

Recursive clone isn't always sufficient. Consider a hash table with a bucket array of linked lists:

public class HashTable implements Cloneable { private Entry[] buckets = ...; private static class Entry { final Object key; Object value; Entry next; Entry(Object key, Object value, Entry next) { this.key = key; this.value = value; this.next = next; } } ... // Kalan kısım çıkarıldı }

Yalnızca kova dizisini özyinelemeli olarak klonlarsanız — Stack'te yaptığımız gibi — klon kendi kova dizisine sahip olacak; ancak bu dizi orijinalle aynı bağlantılı listelere referans verecektir. Bu, hem klonda hem de orijinalde belirsiz davranışa (nondeterministic behavior) kolayca neden olabilir.

If you merely clone the bucket array, the clone and original share the same linked lists — causing nondeterministic behavior.

Dizi Klonlama İdiyomu

array.clone() Java'da dizi çoğaltmanın en iyi yoludur. Dönüş türü orijinal diziyle tamamen aynıdır (dönüştürme gerekmez). Diziler, clone mekanizmasının tek gerçek meşru kullanım alanıdır.

array.clone() is the best way to duplicate arrays. Return type matches the original. Arrays are the sole compelling use of clone.

final Alan Uyumsuzluğu

Cloneable mimarisi, değişebilir nesnelere referans tutan final alanlarla uyumsuzdur. clone metodu alana yeni değer atayamaz — final bir kez atanınca değiştirilemez. Bir sınıfı klonlanabilir yapmak için bazı final değiştiricileri kaldırmanız gerekebilir — bu tasarım ödünleşmesi (trade-off) ideal değildir.

Cloneable is incompatible with final fields referencing mutable objects. clone can't reassign final fields. You may need to remove final modifiers — not ideal.
