Chapter 8 — Metotlar (Methods)

Bölüm 8: Metotlar

Bu bölüm metot tasarımının çeşitli yönlerini ele alır: parametreleri ve dönüş değerlerini nasıl ele almalı, metot imzalarını nasıl tasarlamalı ve metotları nasıl belgelemelisiniz.

This chapter covers method design: parameters, return values, signatures, and documentation.

Madde 49: Parametrelerin Geçerliliğini Kontrol Edin

Item 49: Check parameters for validity

Metotların ve yapıcıların çoğu, parametre değerleri üzerinde kısıtlamalar gerektirir. Bu kısıtlamaları metodun başında kontrol edin — hatayı mümkün olan en erken noktada yakalayın. Genel (public) metotlar için @throws Javadoc etiketi ile belgelendirin.

Java 7'den itibaren Objects.requireNonNull kullanarak null kontrolü yapabilirsiniz. Java 9'da checkFromIndexSize, checkFromToIndex ve checkIndex eklendi.

Özel metotlarda parametreleri assert (iddia) ile kontrol edin — başarısız olduğunda AssertionError fırlatır ve performans maliyeti yoktur (devre dışı bırakılabilir).

Madde 50: Gerektiğinde Savunmacı Kopyalar Yapın

Item 50: Make defensive copies when needed

Java güvenli bir dildir, ama istemcilerinizin sınıfınızın değişmezlerini (invariants) bozmaya çalışacağını varsayın. Değiştirilebilir nesneleri parametre olarak alıyorsanız, bunların savunmacı kopyalarını (defensive copies) yapın:

// Savunmacı kopya — değişmezliği korumak için public Period(Date start, Date end) { this.start = new Date(start.getTime()); // Kopya this.end = new Date(end.getTime()); // Kopya if (this.start.compareTo(this.end) > 0) throw new IllegalArgumentException(...); }

Önemli: Kopya önce yapılır, doğrulama sonra — TOCTOU (time-of-check / time-of-use) saldırısını önlemek için. Erişimcilerde de savunmacı kopyalar döndürün.

Madde 51: Metot İmzalarını Dikkatli Tasarlayın

Item 51: Design method signatures carefully

Kurallar: Dikkatli isimler seçin, kolaylık metotları aşırıya kaçmayın, uzun parametre listelerinden kaçının (≤4), parametre türleri için sınıflar yerine arayüzleri tercih edin (Map > HashMap), boolean yerine iki elemanlı enum tercih edin.

Madde 52: Aşırı Yüklemeyi Dikkatli Kullanın

Item 52: Use overloading judiciously

Aşırı yükleme (overloading) derleme zamanında, ezme (overriding) çalışma zamanında çözülür! Bu fark kafa karıştırıcıdır. Güvenli kural: Aynı parametre sayısıyla iki aşırı yükleme sağlamayın. Varargs metotları hiç aşırı yüklemeyin. İstemciler hangi aşırı yüklemenin çağrılacağını bilmek zorunda kalmamalıdır.
