Madde 24: Statik Üye Sınıflarını Statik Olmayanlara Tercih Edin

Item 24: Favor static member classes over nonstatic

İç sınıfların (nested classes) dört çeşidi vardır:

1. Statik üye sınıfları (static member classes): En yaygın tür. Dış sınıfın bir yardımcısı olarak düşünün. Dış sınıfa başvuru tutmazlar. Map uygulamalarındaki Entry nesneleri güzel bir örnektir — her giriş bir harita ile ilişkilidir ama Entry metotlarının haritanın kendisine erişmesi gerekmez.

2. Statik olmayan üye sınıfları (nonstatic member classes): Her örnek, çevreleyen sınıfın bir örneğiyle örtük olarak ilişkilidir. İç örnek, dış örneğin metotlarını çağırabilir ve OuterClass.this ile ona referans alabilir. Dikkat: Çevreleyen örneğe referans fazladan bellek tüketir ve çöp toplayıcının (GC) dış örneği toplamasını engelleyebilir — gizli bellek sızıntısı!

3. Anonim sınıflar (anonymous classes): Adı olmayan, bildirildikleri yerde anlık olarak oluşturulan sınıflar. Lambda'lardan önce küçük işlev nesneleri (function objects) için kullanılırdı. Artık lambda ifadeleri her zaman tercih edilmelidir (Madde 42).

4. Yerel sınıflar (local classes): Bir blok içinde bildirilen, en az kullanılan çeşit.

Kural: İç sınıfın dış örneğe erişmesi gerekmiyorsa, static yapın. Aksi halde her iç sınıf örneği dış örneğe gizli bir referans taşır — bellek ve performans maliyeti!

Four kinds: 1) Static member classes (no enclosing instance ref). 2) Nonstatic member classes (hidden ref to enclosing instance — memory leak risk!). 3) Anonymous classes (prefer lambdas). 4) Local classes (rare). Rule: if no access to enclosing instance needed, make it static.

Madde 25: Kaynak Dosyalarını Tek Bir Üst Düzey Sınıfla Sınırlayın

Item 25: Limit source files to a single top-level class

Java derleyicisi tek bir kaynak dosyada birden çok üst düzey sınıf tanımlamanıza izin verse de, bunu yapmanın hiçbir faydası yoktur ve ciddi riskleri vardır. Risk, bir sınıfa birden çok tanım sağlama olasılığından kaynaklanır — hangi tanımın kullanılacağı dosyaların derleyiciye verilme sırasına bağlıdır.

Java allows multiple top-level classes in one file, but it's risky — which definition is used depends on compilation order.

// Main.java public class Main { public static void main(String[] args) { System.out.println(Utensil.NAME + Dessert.NAME); } } // Utensil.java — her sınıf kendi dosyasında olmalı! class Utensil { static final String NAME = "pot"; } class Dessert { static final String NAME = "pie"; }

Çözüm basittir: Asla tek bir kaynak dosyaya birden fazla üst düzey sınıf koymayın. Alternatif olarak, statik üye sınıflarını kullanabilirsiniz. Bu, programınızın derleme sırasından bağımsız olarak aynı davranacağını garanti eder.

4 İç Sınıf Çeşidi

1. Statik üye sınıfı: static class Inner — dış örneğe referansı yok. En güvenli ve en yaygın.
2. Statik olmayan üye sınıfı: class Inner — dış örneğe gizli referans taşır. Bellek sızıntısı riski!
3. Anonim sınıf: Artık lambda kullanın.
4. Yerel sınıf: Blok içinde tanımlı, nadiren kullanılır.

Altın kural: Dış örneğe erişim gerekmiyorsa → static yapın!

1) Static member class — no enclosing ref. 2) Nonstatic — hidden ref, memory risk. 3) Anonymous — use lambdas. 4) Local — rare. Rule: if no enclosing access needed, use static.
