Geçişlilik (Transitivity) — equals sözleşmesinin üçüncü gereksinimi, bir nesne ikincisine eşitse ve ikincisi üçüncüye eşitse, birincinin de üçüncüye eşit olması gerektiğini söyler. Yine, bu gereksinimi yanlışlıkla ihlal etmeyi hayal etmek zor değildir. Üst sınıfına (superclass) yeni bir değer bileşeni (value component) ekleyen bir alt sınıf (subclass) örneğini düşünün. Başka bir deyişle, alt sınıf equals karşılaştırmalarını etkileyen bir bilgi parçası ekler. Basit, değişmez (immutable), iki boyutlu bir tamsayı nokta sınıfı ile başlayalım:

Transitivity — The third requirement of the equals contract says that if one object is equal to a second and the second object is equal to a third, then the first object must be equal to the third. Again, it's not hard to imagine violating this requirement unintentionally. Consider the case of a subclass that adds a new value component to its superclass. Let's start with a simple immutable two-dimensional integer point class:

public class Point { private final int x; private final int y; public Point(int x, int y) { this.x = x; this.y = y; } @Override public boolean equals(Object o) { if (!(o instanceof Point)) return false; Point p = (Point) o; return p.x == x && p.y == y; } ... // Kalan kısım çıkarıldı }

Bu sınıfı genişleterek (extend) bir noktaya renk kavramını eklemek istediğinizi varsayalım:

Suppose you want to extend this class, adding the notion of color to a point:

public class ColorPoint extends Point { private final Color color; public ColorPoint(int x, int y, Color color) { super(x, y); this.color = color; } ... // Kalan kısım çıkarıldı }

equals metodu nasıl görünmeli? Tamamen atlarsanız, uygulama Point'ten miras alınır ve renk bilgisi equals karşılaştırmalarında yok sayılır. Bu, equals sözleşmesini ihlal etmese de, açıkça kabul edilemez. Yalnızca argümanı aynı konuma ve renge sahip başka bir ColorPoint ise true döndüren bir equals metodu yazdığınızı varsayalım:

How should the equals method look? If you leave it out entirely, the implementation is inherited from Point and color information is ignored. While this does not violate the contract, it is clearly unacceptable. Suppose you write an equals method that returns true only if its argument is another color point with the same position and color:

// Hatalı — simetriyi ihlal eder! @Override public boolean equals(Object o) { if (!(o instanceof ColorPoint)) return false; return super.equals(o) && ((ColorPoint) o).color == color; }

Bu metodun sorunu, bir noktayı bir renkli noktayla karşılaştırırken ve tam tersini yaparken farklı sonuçlar alabilmenizdir. İlk karşılaştırma rengi yok sayar, ikincisi ise argümanın türü yanlış olduğu için her zaman false döndürür. Somutlaştıralım: bir nokta ve bir renkli nokta oluşturalım:

The problem with this method is that you might get different results when comparing a point to a color point and vice versa. The former comparison ignores color, while the latter always returns false because the type is incorrect. Let's create one point and one color point:

Point p = new Point(1, 2); ColorPoint cp = new ColorPoint(1, 2, Color.RED); // p.equals(cp) → true (rengi yok sayar) // cp.equals(p) → false (p ColorPoint değil!) // SİMETRİ İHLALİ!

🔍 Kavramlar: 🔍 Concepts:

Geçişlilik (Transitivity)

Geçişlilik: A = B ve B = C ise → A = C olmalıdır. Alt sınıf bir değer bileşeni eklediğinde (örn. color), bu kuralı ihlal etmemek son derece zorlaşır.

Point → ColorPoint problemi, nesne yönelimli dillerde denklik ilişkilerinin temel bir sorunudur. Çözüm: kalıtım yerine bileşim (composition over inheritance).

Transitivity: if A = B and B = C → A = C. When a subclass adds a value component (e.g., color), preserving this rule becomes extremely difficult.

The Point → ColorPoint problem is a fundamental issue with equivalence relations in OOP. Solution: composition over inheritance.

Değer Bileşeni Ekleme Sorunu

Bir alt sınıf, üst sınıfına equals karşılaştırmasını etkileyen yeni bir alan (değer bileşeni) eklediğinde, iki seçenek vardır:

1. Rengi yok say: equals sözleşmesi tutarlı kalır ama anlamsızdır — farklı renkteki iki nokta "eşit" olur.

2. Rengi dahil et: Ya simetri ya da geçişlilik ihlal edilir. Bu kaçınılmaz bir ikilemdir.

When a subclass adds a new field (value component) to its superclass that affects equals, there are two options:

1. Ignore color: Contract is consistent but meaningless — two points with different colors are "equal".

2. Include color: Either symmetry or transitivity is violated. This is an unavoidable dilemma.

💡 Çözüm: Alt sınıf yerine bileşim (composition) kullanın — ColorPoint sınıfını Point'ten genişletmek yerine, içinde bir Point alanı tutan bir sınıf olarak tasarlayın (Madde 18).
