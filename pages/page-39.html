↩ Önceki sayfadan devam — Madde 10: Simetri (Symmetry) — CaseInsensitiveString örneği

...büyük/küçük harfe duyarsız (case-insensitive) bir string uygulayan aşağıdaki sınıfı düşünün. String'in büyük/küçük harf durumu toString tarafından korunur ancak equals karşılaştırmalarında göz ardı edilir:

...consider the following class, which implements a case-insensitive string. The case of the string is preserved by toString but ignored in equals comparisons:

// Hatalı — simetriyi ihlal eder! // Broken - violates symmetry! public final class CaseInsensitiveString { private final String s; public CaseInsensitiveString(String s) { this.s = Objects.requireNonNull(s); } // Hatalı — simetriyi ihlal eder! @Override public boolean equals(Object o) { if (o instanceof CaseInsensitiveString) return s.equalsIgnoreCase( ((CaseInsensitiveString) o).s); if (o instanceof String) // Tek yönlü birlikte çalışılabilirlik! return s.equalsIgnoreCase((String) o); return false; } ... // Kalan kısım çıkarıldı }

Bu sınıftaki iyi niyetli equals metodu, saf bir şekilde sıradan string'lerle birlikte çalışmaya (interoperate) çalışır. Bir adet büyük/küçük harfe duyarsız string ve bir adet sıradan string olduğunu varsayalım:

The well-intentioned equals method in this class naively attempts to interoperate with ordinary strings. Let's suppose that we have one case-insensitive string and one ordinary one:

CaseInsensitiveString cis = new CaseInsensitiveString("Polish"); String s = "polish";

Beklediğiniz gibi, cis.equals(s) true döndürür. Sorun şu ki, CaseInsensitiveString'deki equals metodu sıradan string'leri tanırken, String'deki equals metodu büyük/küçük harfe duyarsız string'lerden habersizdir (oblivious). Bu nedenle, s.equals(cis) false döndürür — açık bir simetri ihlali.

Büyük/küçük harfe duyarsız bir string'i bir koleksiyona koyduğunuzu varsayalım:

As expected, cis.equals(s) returns true. The problem is that while the equals method in CaseInsensitiveString knows about ordinary strings, the equals method in String is oblivious to case-insensitive strings. Therefore, s.equals(cis) returns false, a clear violation of symmetry.

Suppose you put a case-insensitive string into a collection:

List<CaseInsensitiveString> list = new ArrayList<>(); list.add(cis);

Bu noktada list.contains(s) ne döndürür? Kim bilir? Mevcut OpenJDK uygulamasında false döndürür; ancak bu yalnızca bir uygulama detayıdır (implementation artifact). Başka bir uygulamada kolayca true döndürebilir veya çalışma zamanı istisnası fırlatabilir. Bir kez equals sözleşmesini ihlal ettiniz mi, diğer nesnelerin sizin nesnenizle karşılaştığında nasıl davranacağını bilemezsiniz.

Sorunu ortadan kaldırmak için, equals metodundan String ile birlikte çalışma girişimini kaldırmanız yeterlidir. Bunu yaptığınızda, metodu tek bir return ifadesine yeniden düzenleyebilirsiniz (refactor):

What does list.contains(s) return at this point? Who knows? In the current OpenJDK implementation, it happens to return false, but that's just an implementation artifact. In another implementation, it could just as easily return true or throw a runtime exception. Once you've violated the equals contract, you simply don't know how other objects will behave when confronted with your object.

To eliminate the problem, merely remove the ill-conceived attempt to interoperate with String from the equals method. Once you do this, you can refactor the method into a single return statement:

// Doğru — yalnızca kendi türüyle karşılaştırır @Override public boolean equals(Object o) { return o instanceof CaseInsensitiveString && ((CaseInsensitiveString) o).s.equalsIgnoreCase(s); }

🔍 Kavramlar: 🔍 Concepts:

Simetri İhlali (Symmetry Violation)

CaseInsensitiveString → String karşılaştırmasında true, ancak String → CaseInsensitiveString karşılaştırmasında false döner. Bu, x.equals(y) != y.equals(x) anlamına gelir — simetri ihlali!

Sonuç: Koleksiyonlar öngörülemez davranır. ArrayList bir JVM'de false, başka bir JVM'de true döndürebilir veya istisna fırlatabilir.

CaseInsensitiveString → String returns true, but String → CaseInsensitiveString returns false. This means x.equals(y) != y.equals(x) — symmetry violation!

Result: Collections behave unpredictably. ArrayList may return false in one JVM, true in another, or throw an exception.

Türler Arası Eşitlik Tuzağı

equals metodunda farklı türlerle (cross-type) eşitlik sağlamaya çalışmak neredeyse her zaman yanlıştır. CaseInsensitiveString, String ile eşit olmaya çalıştı; ancak String bu eşitliği bilmediği için simetri bozuldu.

Attempting cross-type equality in equals is almost always wrong. CaseInsensitiveString tried to be equal to String, but String didn't know about this equality, breaking symmetry.

💡 Kural: equals metodu yalnızca kendi sınıfının örnekleriyle (instanceof kontrolü ile) karşılaştırma yapmalıdır. Başka türlerle birlikte çalışmaya çalışmayın.
