Item 18: Favor composition over inheritance

Kalıtım (inheritance) kodu yeniden kullanmanın güçlü bir yoludur; ancak her zaman iş için en iyi araç değildir. Arayüz kalıtımı (bir sınıfın arayüz uygulaması veya bir arayüzün diğerini genişletmesi) güvenlidir. Burada tehlikeli olan uygulama kalıtımıdır (implementation inheritance) — bir sınıfın başka bir sınıfı genişlettiği durum.

Paket sınırları içinde kalıtım güvenlidir — üst sınıf ve alt sınıf aynı programcının kontrolü altındaysa. Kalıtım ayrıca genişletilmek için özel olarak tasarlanmış ve belgelenmiş sınıflar için de güvenlidir (Madde 19). Ancak, sıradan somut sınıfları paket sınırları ötesinde genişletmek tehlikelidir.

Kalıtım, kapsüllemeyi kırar. Bir alt sınıf, doğru çalışması için üst sınıfının uygulama detaylarına bağlıdır. Üst sınıfın uygulaması sürümden sürüme değişebilir ve alt sınıf — koduna dokunulmadığı halde — bozulabilir.

Somut bir örnek olarak, eklediğimiz tüm öğeleri saymak istediğimiz bir HashSet düşünelim:

Inheritance is powerful for code reuse but not always the best tool. Interface inheritance is safe. Implementation inheritance across package boundaries is dangerous because it violates encapsulation. A subclass depends on its superclass's implementation details.

// Bozuk! — Kalıtımın yanlış kullanımı public class InstrumentedHashSet<E> extends HashSet<E> { private int addCount = 0; @Override public boolean add(E e) { addCount++; return super.add(e); } @Override public boolean addAll(Collection<? extends E> c) { addCount += c.size(); return super.addAll(c); } public int getAddCount() { return addCount; } }

addAll ile 3 eleman eklersek getAddCount() 6 döndürür, 3 değil! Çünkü HashSet.addAll içeride add'i çağırır — bizim ezdiğimiz add'i. Böylece her eleman iki kez sayılır. Bu, HashSet'in iç uygulama detayına bağlılıktan kaynaklanan bir sorundur.

Çözüm: Bileşim (Composition). Mevcut sınıfı genişletmek yerine, yeni sınıfa mevcut sınıfın bir örneğini tutan özel bir alan ekleyin. Bu yaklaşım sarmalama (wrapping) veya Dekoratör deseni (Decorator pattern) olarak da bilinir:

addAll with 3 elements returns 6 because HashSet.addAll internally calls add, which we overrode. Solution: composition (wrapping / Decorator pattern).

🔍 Kavramlar: 🔍 Concepts:

Kendi Kendini Kullanma (Self-use)

Bir sınıfın genel metotlarının birbirini çağırmasına kendi kendini kullanma (self-use) denir. HashSet.addAll() içeride add()'i çağırır — bu bir kalıtım tuzağıdır çünkü alt sınıf add'i ezerse, addAll davranışı değişir. Üst sınıflar bu tür iç bağımlılıkları belgelemezlerse kalıtım güvenli olmaz.

Self-use: HashSet.addAll() calls add() internally. If subclass overrides add, addAll behavior changes unexpectedly.

Dekoratör Deseni

Dekoratör (Decorator) deseni, bir nesneyi sarmalayarak (wrapping) yeni davranışlar ekler. Kalıtım yerine bileşim kullanır:

• İç nesneye bir alan referansı tutar
• Tüm metotları iç nesneye delege eder (forwarding)
• İstenen metotlarda ek davranış ekler

Kalıtım kırılgandır; dekoratör esnektir ve üst sınıf değişikliklerinden etkilenmez.

Decorator wraps an object, delegates methods, adds behavior. Unlike inheritance, it's resilient to superclass changes.
